# 2–3주차 — 측정 기반의 동결, 그리고 연합학습 파이프라인

**과제:** 검색 계산으로 통신량을 되사기 — 연합 LLM 미세조정에서 클라이언트 측
재순위의 환율

**범위:** Subtask 1.1 (코퍼스, 클라이언트 분할, 인덱스, 검색 캐시) 및
Subtask 1.3 (연합학습 파이프라인과 그 검증)

---

## 1. 두 주차의 위치

1주차는 이 질문이 답할 수 있는 질문임을 확인했다. 재순위가 메울 수 있는 성능
격차가 존재하고, 깊이가 커지면 검색이 단조 개선되며, 클라이언트 업데이트가
측정 가능하게 구별되는 로컬 스텝 설정이 존재한다. 2–3주차는 그 측정을 실제로
만들어 낼 장치를 구축한다.

| 주차 | 산출물 | 소비처 |
|---|---|---|
| 2 | 고정된 코퍼스, 클라이언트 분할, 인덱스, **동결된 검색 캐시** | 모든 본실험 run |
| 3 | 연합학습 파이프라인, **1회 run 으로 전 구간 검증** | 16 회의 본실험 run |

두 주차의 목적은 하나로 모인다. **본실험이 시작될 때, 조건 간에 달라지는 것이
재순위 깊이 외에는 없어야 한다.**

## 2. 2주차 — 측정 기반

### 2.1 검색 캐시를 한 번만 계산하고 동결하는 이유

재순위는 각 클라이언트의 **학습 입력**에 적용된다. 만약 검색을 본실험 run 안에서
매번 다시 수행한다면, 두 조건은 깊이에서도 다르고 그때 검색이 무엇을 돌려주었는
지에서도 달라진다. 그러면 측정된 효과를 깊이에 귀속시킬 수 없다.

따라서 후보 풀, dense 점수, 교차인코더 점수를 분할마다 한 번 계산해 저장한다.
본실험 run 은 이를 읽어 **재배열만** 한다.

```
질문 1개당:  dense 상위 50 후보  +  dense 점수 50개  +  교차인코더 점수 50개
```

| 분할 시드 | 클라이언트당 질문 | 교차인코더 forward 횟수 | 소요 시간 |
|---|---|---|---|
| 1001 | 9,844 | 3,937,600 | 66분 |
| 1002 | 9,742 | 3,896,800 | 65분 |

여기서 두 가지가 따라온다. 첫째, 모든 조건이 **바이트 단위로 동일한** 검색 결과를
본다. 둘째, 학습 중에 깊이는 라운드당 비용을 **전혀 추가하지 않는다** — 점수가
이미 존재하므로 `d = 50` 과 `d = 0` 의 학습 속도가 같고, 재순위 계산량은 벽시계
시간에 뒤섞이지 않고 비용 모델에서 별도로 회계된다.

### 2.2 코퍼스

passage 200,000개. 재순위가 할 일이 남아 있도록, 그리고 음성 예제가 정답을
누출할 수 없도록 구성했다.

| 구성 | 개수 | 역할 |
|---|---|---|
| gold | 54,129 | 평가 대상 질문의 정답을 포함하는 passage |
| BM25 hard negative | 37,511 | 질문과 어휘적으로 가깝지만 정답이 없음 |
| 무작위 잔여 | 108,360 | 배경 |
| **합계** | **200,000** | |

```
정답을 포함한 음성 예제 위반:  0건
```

hard negative 는 정답 문자열을 포함하지 않는 passage 집합에서 BM25 로 뽑으므로
**구성상 정답이 없으며**, 위반 0건으로 확인했다. 이것이 없으면 검색이 너무 쉬워져
재순위가 되찾을 여유가 사라진다.

gold 수가 질문 수보다 적은 것은 질문들이 passage 를 공유하기 때문이다
(질문당 gold 0.67개).

### 2.3 클라이언트 분할

클라이언트 8개. 무작위가 아니라 **토픽 클러스터**로 분할했다. 주제 이질성이
연합학습이 실제로 놓이는 조건이기 때문이다.

| 속성 | 시드 1001 | 시드 1002 |
|---|---|---|
| 클라이언트당 질문 수 | 9,844 | 9,742 |
| 클라이언트 간 질문 수 편차 | **0** | **0** |
| 클라이언트 간 토픽 분리 | **예** | **예** |
| 자기 클라이언트에 gold 가 있는 질문 비율 | **1.000** | **1.000** |
| 클라이언트당 passage | 22,026 – 26,870 | 22,710 – 28,164 |

세 속성은 의도적으로 강제한 것이다.

- **질문 수 완전 균등(편차 0).** 크기가 다르면 FedAvg 평균이 불안정해지고,
  그것이 두 번째 변동 요인으로 작용한다.
- **gold 가 소유 클라이언트에 존재(1.000).** 정답이 다른 클라이언트에 있는 질문은
  구성상 답할 수 없으며, 모든 조건을 똑같이 조용히 끌어내린다.
- **독립적인 분할 2개.** 결과를 두 분할에서 함께 보고하므로, 어떤 결론도 특정
  배분 하나에 의존하지 않는다.

따라서 클라이언트 이질성은 **고정된 배경 조건이며 요인(factor)이 아니다.**

**두 분할의 클라이언트당 질문 수가 다른 이유.** 균등은 모든 클라이언트를 **가장
작은 클라이언트의 크기로 절삭**해서 강제한다. 따라서 공통 크기는 가장 적게 배정된
클라이언트가 가진 수가 된다. 시드가 토픽 클러스터링과 클러스터→클라이언트 배분을
결정하므로 그 최소 클라이언트가 분할마다 달라진다. 시드 1001 에서 9,844, 1002 에서
9,742 로 **102 개 차이(1.0 %)** 다. 절삭으로 버려지는 질문은 첫 분할에서 1,968 개
(2.4 %), 두 번째에서 2,784 개(3.4 %) 다. 분할 **내부**의 정확한 균등을 얻기 위한
비용이며, 클라이언트 크기가 두 번째 변동 요인으로 작용하지 않게 하려고 지불한다.

분할 간의 이 차이는 depth 비교에 도달하지 않는다. depth 는 **같은 시드 안에서**
비교되고 한 시드는 하나의 분할만 쓰므로, 1 % 의 크기 차이는 분할 간의 수준 차이이며
쌍체 비교가 제거한다.

### 2.4 인덱스

클라이언트별·분할 시드별로 벡터 인덱스를 하나씩 구축해, 각 클라이언트가 자기
passage 에서만 검색하도록 했다. 컬렉션별 passage 수는 위 표와 같다.

### 2.5 2주차가 측정한 것: 검색 여유(headroom)

모든 질문은 정확히 세 범주 중 하나에 속하며, 이 셋이 **어떤 재순위 깊이로도
달성 가능한 한계**를 규정한다.

| 범주 | 시드 1001 | 시드 1002 | 의미 |
|---|---|---|---|
| `already` | 0.5043 | 0.5067 | gold 가 이미 dense 상위 3개에 있음 — 재순위가 할 일이 없음 |
| `recoverable` | **0.2287** | **0.2248** | gold 가 상위 50 풀에는 있으나 상위 3개에는 없음 — **재순위가 되찾을 수 있음** |
| `out_of_pool` | 0.2669 | 0.2685 | gold 가 풀에 없음 — 어떤 깊이로도 도달 불가 |
| **천장** | **0.7331** | **0.7315** | `already + recoverable`, 모든 조건이 공유 |

본실험 결과는 이 틀 안에서 읽어야 한다. 재순위에 허용된 최대 개선폭은
**22.87 %p** 이며, 천장은 조건 간에 동일하다. 이것을 모르면 몇 %p 의 개선이 큰지
작은지 판정할 수 없다.

### 2.6 깊이 사다리 실측

**0, 3, 10, 50 을 고른 이유.** 네 값 중 셋은 선택이 아니라 설계가 정한 값이다.

| `d` | 결정 요인 | 다른 값일 수 없는 이유 |
|---|---|---|
| 0 | — | 기준선: 재순위 없는 dense 검색 |
| **3** | `top_k = 3` | 순서 통제는 **정확히 `top_k`** 에서만 성립한다. 그보다 작으면 재채점되지 않는 프롬프트 슬롯이 남고, 크면 네 번째 passage 가 승격되어 순서 통제가 아니게 된다. `d = top_k` 만이 `promotion = 0` 과 `rank_change > 0` 을 동시에 준다 |
| **50** | `candidate_pool = 50` | 후보 풀 전체. 그 바깥에는 재채점할 것이 없다 |
| 10 | 자유 선택 | 유일한 내부 점. 3 과 50 사이에 대략 등비로 놓았다 |

따라서 사다리는 **재순위 없음 → 순서만 바꿈 → 풀의 일부 → 풀 전체** 다. 풀 자체를
50 으로 고정한 것은 재순위 FLOPs 가 풀 크기에 비례하고 그 FLOPs 가 환율의 **비용
쪽** 이기 때문이다. 풀을 키우면 천장이 올라가지만(실측: 50 에서 0.669, 100 에서
0.721, 200 에서 0.774) 본 과제가 내주는 계산량도 함께 커진다.

프롬프트 3개 슬롯에서의 gold recall, 클라이언트 8개 평균:

| 깊이 `d` | 시드 1001 | 시드 1002 |
|---|---|---|
| 0 | 0.5043 | 0.5067 |
| **3** | **0.5043** | **0.5067** |
| 10 | 0.5349 | 0.5368 |
| 50 | **0.5435** | **0.5455** |

```
d=50 의 이득   =  0.5435 − 0.5043  =  +3.92 %p
되찾을 수 있던 양 =  0.2287
포착률         =  0.0392 / 0.2287  =  되찾을 수 있던 것의 17.1 %
```

**`d = 0` 과 `d = 3` 이 소수점 네 자리까지 동일하며, 두 분할의 16개 클라이언트
전부(16/16)에서 그렇다.** 이는 순서 통제(ordering control)의 설계된 동작이다.
dense 가 이미 고른 3개를 재채점해도 네 번째 passage 를 올릴 수 없으므로, 프롬프트는
순서만 달라진 **동일한 3개**를 담는다. 따라서 이 조건은 순서 효과와 실제 검색 품질
효과를 분리하며, 측정은 그 분리가 성립함을 확인한다.

두 분할이 전 구간에서 소수점 세 자리까지 일치하므로, 이 값들은 특정 배분에
의존하지 않는다.

## 3. 3주차 — 파이프라인

### 3.1 한 라운드가 하는 일

```
각 라운드 r = 1 … R 에 대해:
    각 클라이언트 i = 1 … 8 에 대해:
        전역 어댑터를 받는다
        클라이언트 i 의 질문으로만 K = 32 회 로컬 갱신
        갱신된 어댑터를 돌려준다
    FedAvg: 어댑터 8개를 평균
    r 이 평가 스케줄에 있으면: 전역 모델을 중앙에서 채점
```

따라서 한 라운드는 8 × 32 = 256 회의 가중치 갱신이며, 각 갱신은 유효 배치
8개 예제를 소비한다.

### 3.2 측정을 지탱하는 설계 결정

**고정 통신 예산, early stopping 없음.** 모든 조건이 동일한 R, N, payload 를
소모한다. 비교하는 것은 *어느 조건이 먼저 수렴하는가* 가 아니라 *같은 예산이
무엇을 사주는가* 이다. 조건마다 다른 지점에서 멈추게 하면 예산 자체가 변동 요인이
된다.

**K, S, R 은 1주차 교정 결과에서 주입되며 손으로 설정하지 않는다.** 파이프라인이
게이트 산출물에서 읽으므로, 본실험에 쓰인 값은 게이트가 정당화한 값이다.

```
S  =  (클라이언트당 질문 수 ÷ 유효 배치) × 패스 수  =  1,892
R  =  S ÷ K  =  1,892 ÷ 32  =  59
```

**평가는 중앙에서, 탐욕 디코딩으로, 전 조건 `d = 0` 에서 수행한다.** 서버가 평균된
전역 모델을 고정 held-out 집합에서 채점한다. 평가 컨텍스트를 `d = 0` 으로 고정하는
것은 *모델이 배운 것* 과 *추론 시점에 더 좋은 컨텍스트가 공급한 것* 을 분리하기
위해서다. `d = 50` run 을 `d = 50` 에서 평가하면 점수가 오르지만, 그것은 시험
시점에 더 좋은 문서를 준 결과이며 통신량과는 무관하다.

**Answer F1 을 주 지표로, EM 을 함께 기록한다.** 5주차는 "어떤 조건이 목표 `τ` 에
처음 도달한 라운드" 를 선형 보간으로 읽는다. F1 은 연속값이어서 보간이 안정적이고,
EM 은 계단 함수여서 라운드 추정값을 튀게 만든다.

**옵티마이저 상태는 라운드를 넘어 유지된다.** AdamW 의 모멘텀을 매 라운드 초기화하면
각 클라이언트가 매번 처음부터 시작하게 되며, 이는 연합학습의 동작이 아니다.

**모델 인스턴스 하나가 8개 클라이언트를 담당하며** 파라미터만 교체한다. 135M 모델
8벌은 어댑터만 다를 뿐이고, 그렇게 하지 않으면 메모리가 실험 규모를 제약한다.

**검색 캐시는 분할 시드로 키가 매겨진다.** 따라서 어떤 분할이 다른 분할의 캐시와
짝지어질 수 없다.

### 3.3 train / val / test

세 집합은 파일로 존재하며 서로 겹치지 않는다.

| 집합 | 규모 | 용도 |
|---|---|---|
| **val** | 2,000 | 1주차 게이트 결정 — K, R, 깊이 사다리를 여기서 선택했다 |
| **test** | 1,000 | 최종 비교 전용. 어떤 결정에도 쓰이지 않는다 |
| **train** | 잔여 | 클라이언트 8개에 배분 |

분리는 코드에서 강제된다. 평가셋은 val 질문 id 를 제외하고 구성되며, 그 평가 질문
id 는 다시 모든 클라이언트의 학습 예제에서 제거된다. val 집합의 존재 이유가
바로 이것이다. **1주차의 선택이 최종 측정에 쓰이는 집합에 포함되지 않은 질문에서
이루어졌으므로, 어떤 파일럿 결정도 보고된 결과를 부풀릴 수 없다.**

### 3.4 통신량 회계

```
총 바이트  =  R × N × (|A| + |B|) × 파라미터당 바이트 × 2
           =  59 × 8 × 921,610 × 2 × 2
           =  run 1회당 1.7400 GB
```

`|A| + |B|` 는 **합**이다. LoRA 어댑터는 두 인자 행렬을 **둘 다** 전송하므로
payload 는 원소 개수의 합이며 곱이 아니다. SmolLM2-135M 의 attention projection 에
rank 8 을 적용하면 921,610개 파라미터이고, fp16 에서 1.84 MB 로 기저 모델의
0.7 % 이다. 파이프라인은 이 총량을 라운드 로그에서 독립적으로 재계산해 두 값이
일치하는지 확인한다.

이것이 본 과제가 거래하는 대상이다. 기존 수단 — PEFT, 양자화, 희소화 — 은 모두
라운드당 payload 를 줄인다. 본 과제는 **라운드 수 `R`** 을 공격한다.

### 3.5 검증 run

`d = 10`, 시드 1 로 1회 완주해, 파이프라인이 분석에 쓸 수 있는 기록을 생산하는지
확인했다.

| 항목 | 값 |
|---|---|
| 완료 라운드 | 59 / 59 |
| Answer F1 | 0.54 (학습 전) → **28.94** |
| EM | 21.90 |
| 통신량 | **1.7400 GB**, 수식과 독립 계산이 일치 |
| `promotion_rate` | 0.4201, 라운드 간 상수 |
| `rank_change_rate` | 0.677 |
| 클라이언트 업데이트 발산 | 0.343 → 2.476 |
| 보간에 쓸 수 있는 곡선 점 | 21개 |
| early stopping | 없음 |

세 가지 진단은 가설이 아니라 **장치**를 확인한다.

- `promotion_rate` 가 `d = 10` 에서 0 이 아니므로 처리가 실제로 걸렸고, 검색 캐시가
  동결되어 있으므로 라운드 간 상수다 — 변한다면 결함을 뜻한다.
- 바이트 총량이 독립 계산한 예산 수식과 일치한다.
- 클라이언트 업데이트 발산이 측정 가능하며 학습이 진행되면서 커진다. 이것이
  5주차 기전 점검의 전제 조건이다. 가설은 "검색 품질이 좋아지면 클라이언트들이
  같은 과제를 배우게 되어 덜 발산한다" 이기 때문이다.

### 3.6 이 run 이 확정한 제약

학습 곡선은 **라운드 59 에서도 아직 상승 중**이다. 따라서 5주차의 목표 정확도 `τ`
는 관측된 범위 안으로 제한되며 그 바깥으로 외삽하지 않는다. 어떤 조건이 도달하지
못한 영역은 추정하지 않고 도달하지 못했다고 보고한다.

## 4. 현황과 다음

2–3주차는 완료되었다. 측정 기반이 동결되었고, 파이프라인이 검증되었으며, 세 데이터
분할이 디스크상의 파일로 존재한다.

4주차는 이 장치 위에서 본실험을 실행한다. **깊이 4개 × 시드 4개 = 16 run**, 각각
동일한 1.7400 GB 예산, 총 27.8 GB 의 회계된 통신량이다.

**1–3주차를 작성할 때 행렬은 4 × 5 = 20 이었다.** 스윕의 소요 시간을 줄이기 위해
4 × 4 로 축소했고, 그 수가 16 인 것은 **20 미만에서 유일하게 균형이 맞는 행렬**이기
때문이다. `partition_seed_for` 가 시드를 두 토픽 분할에 번갈아 배정하므로 시드 수가
짝수일 때만 두 분할이 균등하게 쓰인다. 시드 5 개는 depth 마다 1001 이 3 회 /
1002 가 2 회, 3 개는 2:1, 4 개는 2:2 다. 15 run 은 행렬 자체가 되지 않는다 — 4 가
15 를 나누지 않고, 시드를 바깥 루프로 두는 스윕을 거기서 멈추면 처리가 가장 강한
`d50_s4` 가 빠진다.

따라서 이 축소는 원래 계획이 갖고 있던 **불균형도 함께 교정한다.** 시드 5 개였다면
depth 효과를 한쪽 분할에서 더 자주 측정한 셈이 된다. 대가는 시드 5 개 대비 약 12 %
넓은 표준오차(√5⁄√4)이고, 절약은 실측 22.6 시간 스윕에서 5.7 시간이다.

시드 4 개가 부족하다고 판단되면 행렬은 **6 × 4 = 24** 로 확장된다 — 분할 3:3 으로
균형이 맞는 다음 지점이며, 아무것도 다시 돌리지 않는다. 시드가 바깥 루프이고 완료된
run 은 건너뛰므로 새로 추가된 8 run 만 실행된다.

5주차는 16개 곡선을 환율로 변환한다. 주어진 목표에서 절약된 라운드, 그 라운드가
뜻하는 통신량, 그리고 그 대가로 지불한 재순위 FLOPs 를 — 단일 판정이 아니라
**운영 구간** 으로 보고한다.
