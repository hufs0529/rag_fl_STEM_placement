# Week 1 보고서 — 파일럿 게이트와 데이터 준비

**연구 제목** 검색 계산으로 통신을 사다: 연합 LLM 미세조정에서 클라이언트측 재순위화의 환율
*(Buying Back Communication with Retrieval Compute: The Exchange Rate of Client-Side Reranking in Federated LLM Fine-Tuning)*

---

## 0. 요약

연합학습의 총 통신량은 `R × N × |AB| × 2` 이다. 선행 연구는 대부분 라운드당 전송량 `|AB|`
를 줄이는 데 집중해 왔다. 이 연구는 대신 **라운드 수 `R`** 을 공격한다. 클라이언트에서
검색 품질을 높이면 각 클라이언트가 더 일관된 과제를 학습하게 되어, 목표 성능에 도달하는
라운드 수가 줄어든다는 가설이다. 그렇다면 **검색에 쓴 연산(FLOP)으로 통신(byte)을 사는
환율**을 측정할 수 있다.

Week 1 의 목적은 본실험을 시작하기 전에 이 설계가 의존하는 전제를 측정으로 확인하는 것이다.
전제가 성립하지 않는다면 본실험 전체가 해석 불가능한 결과를 내므로, 세 개의 파일럿 게이트를
먼저 통과시킨다.

| 게이트 | 확인 대상 | 사전 기준 | 측정값 | 판정 |
|---|---|---|---|---|
| ① 능력 여유 | 기반 모델이 문맥 품질에 반응하는가 | F1 격차 ≥ 5.0 | **18.40** | **통과** |
| ② 깊이 단조성 | 재순위화 깊이가 검색 품질을 올리는가 | recall@3 단조 증가, `recoverable` ≥ 0.10 | **+4.25 %p** (z = 6.00), `recoverable` **0.2020** | **통과** |
| ③ 로컬 스텝 보정 | 어떤 `K` 에서 클라이언트 발산이 관측되는가 | divergence ≥ 0.02 | 1 라운드 측정 완료 (§4) | 진행 중 |

게이트 ①②는 통과했고, 게이트 ③은 1 라운드(교란 없는 측정 구간)가 완료되었다. 본 보고서는
그 1 라운드 결과를 기준으로 작성한다.

## 1. 실험 설계와 처리 축

### 1.1 데이터와 파이프라인

| 자원 | 역할 | 규모 |
|---|---|---|
| `nq_open` | 질문과 정답 (평가 기준) | 학습 질문 91,535 |
| `psgs_w100` (Wikipedia 100-word passages) | 검색 대상 코퍼스 | **21,015,300** |

한 질문의 처리 경로는 다음과 같다.

1. **1차 검색(dense)** — `bge-small-en-v1.5` 로 코퍼스에서 상위 50 권을 뽑는다. 저렴하다.
2. **재순위화(cross-encoder)** — `ms-marco-MiniLM-L-6-v2` 로 상위 `d` 권을 다시 채점한다. 비싸다.
3. **선택** — 재채점 결과 상위 3 권을 프롬프트에 넣는다.

### 1.2 처리 축: 재순위화 깊이 `d`

| `d` | 동작 | 역할 |
|---|---|---|
| **0** | 재순위화 없음 | 기준선 |
| **3** | 상위 3 권만 재채점 | **순서 대조군** — 재정렬만 하고 새 passage 를 승격하지 않는다 |
| **10** | 상위 10 권 재채점 | 처리 |
| **50** | 풀 전체 재채점 | 최대 처리 |

`d = 3` 을 둔 이유는 이 연구의 해석을 지키는 장치이기 때문이다. `d = 10` 이 기준선보다
좋게 나왔을 때 "프롬프트 내 passage 순서가 바뀌어서 좋아진 것"이라는 대안 설명이 가능하다.
`d = 3` 은 **정의상** 상위 3 권의 구성원을 바꾸지 못하고 순서만 바꾸므로, 여기서 성능이
변하지 않으면 순서 효과가 0 이라는 직접 측정이 된다. 그러면 `d = 10`, `d = 50` 의 이득은
전부 **승격(promotion)** 에 귀속된다. §3.3 에서 이 측정을 보고한다.

### 1.3 통제

* 모든 조건은 **동일한 통신 예산** 에서 실행하며 조기 종료를 쓰지 않는다. 조기 종료를 쓰면
  "라운드 수가 줄었다"가 처리 효과인지 정지 규칙의 산물인지 구분되지 않는다.
* 임베더와 재순위화기는 **동결(frozen)** 이고 코퍼스는 정적이다. 따라서 후보 목록과 재채점
  점수를 한 번 계산해 캐시하며, 모든 실행이 **동일한 검색 패스** 를 공유한다. `d` 외의
  어떤 축도 함께 변하지 않는다.
* 목표 도달 라운드 수는 선형 보간으로 구하고, 목표값 `τ` 는 스윕하되 **외삽하지 않는다**.

## 2. 데이터 준비 — 코퍼스 스캔

### 2.1 수행 내용

`psgs_w100` 전체 21,015,300 건을 **단일 패스**로 스캔하여 각 질문의 정답 passage(gold)를
식별했다. 소요 19.3 시간.

| 산출물 | 규모 |
|---|---|
| gold passage | **634,104** |
| 정답 미포함 표본 (reservoir) | 300,000 |
| 사용 가능 학습 질문 | **80,720** / 91,535 (88.2 %) |
| 사용 가능 검증 질문 | 3,356 |
| 질문 커버리지 | **91.85 %** |

표본은 Algorithm R(reservoir sampling)로 추출해 단일 패스에서 균일 표본을 보장했다.

### 2.2 gold 판정 기준을 2 단계로 둔 이유

DPR 계열의 관행은 "정답 문자열이 passage 에 포함되면 gold" 이다. 이 기준을 코퍼스 **전체**
에 적용하면 성립하지 않는다. NQ 정답의 69 % 가 한 토큰이기 때문이다("Paris", "1969", "red").

전수 스캔으로 확인한 결과:

| | 건수 | 비율 |
|---|---|---|
| 정답 문자열이 **전혀 없는** passage | **628** | 0.003 % |
| 정답 문자열을 포함하는 passage | 21,014,672 | **99.997 %** |

즉 문자열 조건만으로는 코퍼스의 거의 전부가 누군가의 gold 가 된다. 그래서 2 단계 기준을 적용했다.

> **1 단계** 정답 문자열 포함 (passage 토큰에 대한 정답 첫 토큰 prefilter)
> **2 단계** 질문의 내용어(content term) **2 개 이상**이 해당 passage 에도 존재

(passage, question) 쌍 단위 결과:

| | 쌍 수 |
|---|---|
| 1 단계 통과 (후보 쌍) | 5,996,794,875 |
| 2 단계까지 통과 (gold 쌍) | **1,130,384** |
| **유지율** | **0.019 %** |

문자열 기준만 쓰면 약 **60 억 개의 거짓 gold 쌍**이 생성된다. 2 단계 기준이 그중
99.98 % 를 제거한다. 두 단계는 동일한 정규화 토큰 목록을 재사용하므로 추가 비용이 거의 없다.

### 2.3 recall 을 문자열 재매칭이 아니라 gold id 로 재는 이유

코퍼스의 채움재(정답 미포함 표본)는 "어느 질문의 gold 도 아닌" passage 이지만, §2.2 에서 보듯
**그중 99.99 % 는 정답 문자열을 포함한다**. 따라서 평가 시 "선택된 passage 에 정답 문자열이
있는가"로 recall 을 재면, 질문과 무관한 임의 passage 가 적중으로 집계된다. 실측 과대계상은
전체 1.9 %, 단일 토큰 정답 질문에서는 6.6 % 였다.

본 연구는 recall 을 **gold passage id 의 소속**으로 판정한다
(`gold_recall_at_k(selected_ids, gold_ids, k)`). 라벨 기준과 측정 기준이 동일해진다.

## 3. 게이트 ② — 깊이 단조성

### 3.1 확인 대상과 방법

이 연구의 처리 축이 실재하는지 확인한다. 즉 `d` 를 0 → 50 으로 올렸을 때 gold passage 가
상위 3 권에 들어가는 비율(`recall@3`)이 **단조 증가**하는가.

학습은 필요 없고 검색만 필요하다. 질문 **2,000 개**를 사용했다. 표본 크기는 쌍체 추정량의
표준오차가 효과를 5 s.e. 이상으로 분해하도록 정했다(§3.4).

**프로브 코퍼스를 Week 2 코퍼스의 축소판으로 구성했다.** 측정하는 난이도가 본실험과 달라지면
게이트가 무의미해지기 때문이다.

| 성분 | 건수 | 비중 |
|---|---|---|
| 표본 질문의 gold (질문당 1 권) | 1,925 | 7.7 % |
| **다른 질문의 gold** | 8,165 | 32.7 % |
| 정답 미포함 채움재 | 14,910 | 59.6 % |
| **합계** | **25,000** | gold 비중 **40.4 %** |

* 크기 25,000 은 Week 2 의 **클라이언트당 인덱스 규모**다.
* gold 비중 40.4 % 는 Week 2 코퍼스(gold 80,720 / 전체 200,000 = 40.36 %)에서 유도한 값이며
  상수로 박지 않았다. 스캔 결과가 달라지면 이 값도 함께 변한다.
* "다른 질문의 gold" 를 채우는 이유는 난이도다. 임의 위키 문서는 이기기 쉽고, 다른 질문의
  정답지는 답이 포함된 글이라 질의와 어휘가 겹쳐 **어렵다**. 이를 넣지 않으면 1 차 검색의
  성적이 과대평가된다.
* 불변식: **표본 질문의 gold 는 한 권도 채움재로 들어가지 않는다.** 질문당 1 권만 라벨로
  유지하므로, 같은 질문의 다른 gold 가 라벨 없이 코퍼스에 있으면 recall 이 과소계상된다.
  판정 로직은 잘리지 않은 원본 gold 목록 전체를 금지 목록으로 쓴다.
* BM25 hard negative 는 **의도적으로 제외**했다. 이들은 gold 를 더 아래로 밀어 `recoverable`
  을 **증가**시키므로, 제외한 측정은 보수적이다. 여기서 통과하면 Week 2 에서는 최소한
  그만큼은 확보된다.

### 3.2 검색 여유의 3 분할

질문을 처리가 영향을 줄 수 있는지에 따라 세 통으로 분해했다. 상한(ceiling)만 보면 "이미
쉬운 질문"과 "재순위화로 건질 수 있는 질문"이 섞이므로 구분이 필요하다.

| 분류 | 정의 | 질문 수 | 비율 | 처리 효과 |
|---|---|---|---|---|
| `already` | gold 가 이미 dense 상위 3 권에 있음 | 934 | 46.70 % | **정확히 0** |
| `recoverable` | gold 가 풀 안에 있으나 상위 3 권 밖 | **404** | **20.20 %** | **유일한 작업 구간** |
| `out_of_pool` | gold 가 후보 풀(50) 밖 | 662 | 33.10 % | **정확히 0** |
| ceiling | `already` + `recoverable` | 1,338 | 66.90 % | 도달 가능 상한 |

`recoverable` = 0.2020 으로 사전 기준 0.10 의 2 배를 확보했다.

### 3.3 결과

| `d` | `recall@3` | 맞힌 질문 | rank-change | promotion |
|---|---|---|---|---|
| **0** | 0.4670 | 934 | 0.000 | 0.000 |
| **3** | **0.4670** | **934** | **0.4375** | **0.000** |
| **10** | 0.4950 | 990 | 0.6647 | 0.4228 |
| **50** | **0.5095** | **1,019** | 0.7157 | 0.5290 |

* `rank-change` 는 선택된 3 칸 중 dense 상위 3 권과 **자리별로** 다른 칸의 비율이다.
* `promotion` 은 선택된 3 칸 중 dense 상위 3 권에 **없던** passage 의 비율이다.

**순서 대조군이 설계대로 작동했다.** `d = 3` 은 선택 결과의 43.75 % 를 재배치했으나
승격률은 0.000 이고, `recall@3` 은 기준선과 소수점 4 자리까지 동일하다. 따라서
`d = 10`, `d = 50` 의 이득은 재정렬이 아니라 승격에 귀속된다.

### 3.4 효과 크기와 불확실성

`d = 0` 과 `d = 50` 은 **같은 질문 집합**에서 측정되므로 두 평균을 독립 표본처럼 다루면
분산을 과대평가한다. 판정이 뒤바뀐 질문만이 차이에 정보를 준다(McNemar 구조).

| 항목 | 값 |
|---|---|
| 처리가 구해낸 질문 (`gained`) | **143** |
| 처리가 망친 질문 (`lost`) | **58** |
| 순증가 | 85 |
| `delta` | **+0.0425** |
| 표준오차 `sqrt(gained + lost) / n` | 0.0071 |
| **z** | **6.00** |

`z = 6.00` 으로 효과는 0 과 명확히 분리된다.

**부수 관찰: 재순위화는 무조건적 개선이 아니다.** 논리적 제약으로 `gained` 143 건은 전부
`recoverable`(404) 에서, `lost` 58 건은 전부 `already`(934) 에서 나온다. `recoverable` 은
기준선에서 이미 틀린 질문이므로 더 망칠 수 없고, `already` 는 이미 맞은 질문이므로 구할 것이
없다. 따라서

| 지표 | 계산 | 값 |
|---|---|---|
| `recoverable` 구조율 | 143 / 404 | **35.4 %** |
| `already` 파괴율 | 58 / 934 | **6.2 %** |
| 순 포착률 (`recoverable_captured`) | 85 / 404 | **21.0 %** |

순 포착률 21.0 % 는 구조 35.4 % 와 파괴 6.2 % 의 상계다. `d` 만 변화시킨 통제된 비교에서만
얻을 수 있는 관찰이며, Week 5 에서 비용·편익 논의의 근거가 된다.

### 3.5 후보 풀 크기 `candidate_pool = 50` 의 근거

`out_of_pool` 이 33.10 % 로 적지 않다. 이 구간은 어떤 `d` 로도 도달할 수 없으므로, 풀을
키우면 상한이 오른다. 처리에 쓰이는 풀보다 깊게 검색해 추가 재채점 없이 민감도를 측정했다.

| `candidate_pool` | `recoverable` | `out_of_pool` | ceiling |
|---|---|---|---|
| **50** (채택) | 0.2020 | 0.3310 | **0.6690** |
| 100 | 0.2535 | 0.2795 | 0.7205 |
| 200 | 0.3070 | 0.2260 | 0.7740 |

50 을 채택한 근거:

1. 사전 기준(`recoverable` ≥ 0.10)을 2 배로 통과하고, 효과가 z = 6.00 으로 확정되었다.
   측정력을 위해 키울 필요가 없다.
2. `candidate_pool` 은 동시에 `d` 의 최댓값이다. 200 으로 올리면 처리 격자가 5 단계가 되어
   실행 수가 20 → 25 로 늘고 비용 모델도 함께 변경된다.
3. `out_of_pool` 은 상한을 0.6690 으로 묶지만, **모든 `d` 가 동일한 상한을 공유**하므로
   `d` 간 비교에는 영향이 없다. 절대 정확도만 제한된다.

따라서 "왜 50 인가"에 대해 관례가 아니라 **측정된 민감도**로 답할 수 있다. 50 에서 상한
0.6690, 200 에서 0.7740 이며, 처리 효과 확인에는 50 이 충분하고 재채색 비용은 1/4 이다.

## 4. 게이트 ③ — 로컬 스텝 보정 (1 라운드)

### 4.1 확인 대상

라운드 수는 자유 변수가 아니다.

```
R = S / K          S: 클라이언트당 총 로컬 스텝,  K: 라운드당 로컬 스텝
```

`K` 가 작으면 클라이언트가 갈라지기 전에 평균되어, **분화를 줄이는 방향으로 작동하는 처리**
의 효과가 보이지 않는다. `K` 가 크면 `R` 이 작아져 목표 도달 라운드 수를 보간할 해상도가
사라진다. 따라서 `K` 는 파일럿으로 정해야 한다.

설정: 클라이언트 8 개 × 질문 250 개, 유효 배치 8, 기준 조건 `d = 0`.
처리가 없는 상태에서 drift 가 관측되는 `K` 를 골라야 처리 효과를 담을 수 있으므로
보정은 기준 조건에서 수행한다.

측정은 **중첩 궤적(nested snapshot)** 방식이다. 한 라운드 안에서는 모든 클라이언트가 동일한
global 파라미터에서 출발하므로, `K = 64` 를 향하는 궤적이 4, 8, 16, 32 스텝 지점을 지나간다.
그 지점의 학습 파라미터를 기록하면 작은 `K` 들의 측정을 추가 학습 없이 얻는다. 클라이언트당
라운드당 비용이 `sum(K) = 124` 에서 `max(K) = 64` 로 줄고, 다섯 `K` 가 **동일 궤적**에서
측정되므로 `K` 간 비교에 난수 궤적 차이가 섞이지 않는다.

이 중첩은 **1 라운드에서만 정확하다**. 2 라운드부터는 출발점이 FedAvg 결과이고 그 결과가
`K` 에 의존하므로 공유가 성립하지 않는다. 따라서 `K` 선택의 근거는 1 라운드 측정이며,
후속 라운드는 "평균 후에도 분화가 유지되는가"에 대한 보강 확인이다.

### 4.2 1 라운드 결과

| `K` | divergence (정규화) | absolute spread | ‖mean update‖ | mean pairwise cosine |
|---|---|---|---|---|
| 4 | 0.5097 | 0.2236 | 0.4925 | +0.764 |
| 8 | 0.3895 | 0.3578 | 0.9859 | +0.850 |
| 16 | 0.3376 | 0.5890 | 1.8415 | +0.883 |
| **32** | **0.3343** (최소) | 0.9641 | 3.0404 | **+0.885** (최대) |
| 64 | **0.4334** (↑) | 1.6042 | 4.0335 | **+0.820** (↓) |

```
divergence = mean_i ‖ δ_i − δ̄ ‖ / ‖ δ̄ ‖        (정규화)
absolute spread = mean_i ‖ δ_i − δ̄ ‖            (정규화 전)
```

두 지표를 함께 기록하는 이유는 `K` 에 대해 반대로 움직이기 때문이다. `K` 가 커지면 각
업데이트가 커져 분모 ‖δ̄‖ 가 커지므로 정규화된 divergence 는 감소하고, 절대 흩어짐은 증가한다.
한쪽만 기록하면 선택 기준을 재검토할 때 전체 스윕을 다시 측정해야 한다.

### 4.3 해석

정규화된 divergence 는 **U 자형**이며 `K = 32` 에서 최소를 지나 `K = 64` 에서 다시 증가한다.
코사인은 거울상으로 `K = 32` 에서 최대(+0.885)를 지나 `K = 64` 에서 감소(+0.820)한다.

| 구간 | 관측 | 해석 |
|---|---|---|
| `K = 4` | divergence 0.510 이 가장 크지만 ‖update‖ 0.49 로 가장 작다 | 업데이트가 작아 **상대적 잡음이 지배**한다. 과제 분화가 아니다 |
| `K = 16–32` | ‖update‖ 가 크고 코사인 최대 | 클라이언트가 **공통 과제를 학습**하고 있다 |
| `K = 64` | 코사인 하락 + 정규화 divergence 상승 | **과제 분화가 시작**된다 |

계획서가 전제한 "너무 작은 `K` 는 갈라지기 전에 평균해버린다"가 수치로 확인되었다.
`K = 4` 의 높은 divergence 는 drift 가 아니라 측정 잡음이다.

### 4.4 `R = S / K` 의 해상도

`S` 는 클라이언트당 총 로컬 스텝이며 클라이언트 데이터를 몇 번 통과하는지로 정의된다.
한 스텝이 소비하는 예제 수는 **유효 배치**, 즉 `batch_size × grad_accumulation = 8` 이다.

```
S = (클라이언트당 질문 수 / 유효 배치) × 패스 수
```

**프로브와 본실험의 규모를 구분해야 한다.** 게이트 ③ 은 프로브이므로 클라이언트당 질문을
250 개로 제한하지만, 본실험에서 각 클라이언트는 사용 가능 질문 80,720 개를 8 로 나눈
약 10,090 개를 받는다.

| | 클라이언트당 질문 | `S` (1.5 패스) | `K = 32` → `R` | `K = 64` → `R` |
|---|---|---|---|---|
| 게이트 ③ 프로브 | 250 | 46 | 1.4 | 0.7 |
| **본실험 (Week 2)** | **10,090** | **1,892** | **59.1** | **29.6** |

목표 도달 라운드 수를 선형 보간으로 추정하려면 통신 예산을 충분히 분해해야 하며,
`R ≥ 20` 이면 해상도가 예산의 5 % 이하가 된다. **본실험 규모에서는 1.5 패스만으로도
`K = 32` 에서 `R = 59`, `K = 64` 에서 `R = 30` 이 확보된다.** 분화가 관측되는 구간과
보간이 가능한 구간이 충돌하지 않는다.

| 패스 수 | `S` | `K = 32` 의 `R` | `K = 64` 의 `R` |
|---|---|---|---|
| **1.5 (현재 설정)** | **1,892** | **59.1** | **29.6** |
| 2 | 2,522 | 78.8 | 39.4 |

**잠정 결론:** `K = 32`, `S = 1,892`(클라이언트 데이터 1.5 패스), `R = 59`. 이 조합은 과제 분화가
관측되는 구간에 있으면서 라운드 해상도 1.7 % 를 확보한다. 계획서의 "`S` 는 클라이언트 데이터
1-2 패스" 를 그대로 유지하므로 설정 변경이 필요하지 않다. 3 라운드 프로브가 완료되면
최종 확정한다.

게이트 ③ 의 산출물은 프로브 규모 `S` 와 본실험 규모 `S` 를 각각 기록한다
(`total_local_steps_full_scale`, `rounds_full_scale_by_K`). 둘을 혼동하면 `R` 이 실제보다
약 40 배 작게 보인다.

### 4.5 결정의 코드 강제

게이트 ③ 은 결과를 `results/logs/gates/calibrated_schedule.json` 에 기록하고, Week 3 · Week 4
실행 스크립트가 이 파일을 직접 읽는다. 따라서 "파일럿이 `K` 와 `R` 을 정했다"는 주장이 문서상
선언이 아니라 실행 경로로 강제된다. 다른 값을 쓰려면 이 산출물을 수정해야 한다.

## 5. 설계 결정과 근거

| 결정 | 값 | 근거 |
|---|---|---|
| 기반 모델 | `SmolLM2-135M-Instruct` | 게이트 ① 이 능력 여유 18.40 F1 확인 |
| 처리 격자 | `d ∈ {0, 3, 10, 50}` | 게이트 ② 가 단조 증가 확인 (+4.25 %p, z = 6.00) |
| `d = 3` 포함 | 순서 대조군 | 순서 효과가 0 임을 직접 측정 (promotion 0.000, recall 불변) |
| 후보 풀 | 50 | 측정된 민감도 (50 → ceiling 0.669, 200 → 0.774); `d` 간 비교는 상한에 무관 |
| gold 판정 | 문자열 + 질문 내용어 2 개 이상 | 문자열 단독 기준은 약 60 억 거짓 쌍을 생성 |
| recall 측정 | gold id 소속 | 채움재의 99.99 % 가 정답 문자열 포함; 문자열 재매칭은 1.9 % 과대계상 |
| 프로브 코퍼스 | 25,000 권, gold 비중 40.4 % | Week 2 의 클라이언트당 인덱스 규모와 구성을 그대로 반영 |
| 효과 통계 | 쌍체(McNemar) | `d = 0` 과 `d = 50` 이 동일 질문 집합을 본다 |
| `K`, `R` | 게이트 ③ 이 결정 | `R = S / K`; 관례가 아니라 파일럿 측정 |
| 배치 구성 | `batch 2 × grad_accum 4` | 유효 배치 8 유지. 등가성은 회귀 테스트로 고정 |

마지막 항목에 대해: CPU 학습에서는 bfloat16 을 쓸 수 없어 float32 로 동작하며, `logits`
텐서가 `batch × seq × vocab × 4 byte` 로 지배항이 된다. 유효 배치를 8 로 유지한 채 미니배치를
2 로 낮추고 기울기를 4 회 누적하면 **동일한 파라미터 갱신**을 얻으면서 피크 메모리를 낮춘다.
두 구성이 같은 가중치를 내는 것은 테스트로 고정되어 있으므로, 이 변경은 메모리 프로파일만
바꾸고 실험 조건을 바꾸지 않는다.
