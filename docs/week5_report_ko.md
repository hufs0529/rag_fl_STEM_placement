# 5주차 — 재순위 계산으로 통신량을 되샀는가

**과제:** 검색 계산으로 통신량을 되사기 — 연합 LLM 미세조정에서 클라이언트 측
재순위의 환율
**범위:** Subtask 1.4

---

## 한 장 요약

**묻는 것.** 연합학습에서 가장 비싼 것은 통신이다. 클라이언트가 **더 좋은 문서로
학습하면 더 적은 라운드로 목표에 도달하고**, 라운드가 줄면 통신량이 준다 — 이것이
이 과제의 가설이다. 문서를 고르는 데는 계산이 든다. 그래서 묻는다:

> **계산을 더 써서 통신량을 얼마나 되샀는가?**

**한 것.** 4 주차가 만든 24 개의 학습 곡선을 읽어, 깊이별로 "같은 점수에 몇 라운드
만에 도달했나" 를 재고, 그 차이를 바이트로 환산해 재순위 계산량과 나눴다.

**나온 것.** **되사지 못했다.** 그리고 어느 고리에서 끊겼는지가 특정된다.

| 가설의 고리 | 결과 |
|---|---|
| 깊이를 올리면 → 더 좋은 문서가 프롬프트에 들어간다 | ✅ **작동** — 새 문서 0 % → 52.5 % |
| 더 좋은 문서 → 모델이 더 잘 배운다 | ❌ **끊김** — 차이가 전부 측정 오차 안 |
| 더 잘 배움 → 라운드가 준다 | ❌ 통제 조건이 가장 자주 "절약" 했다 |
| 라운드 감소 → 통신량 절약 | — 잴 대상이 없다 |

**가장 중요한 한 가지.** `d` = 3 은 **문서를 바꿀 수 없는 조건**이다(이미 고른 3 개를
순서만 바꾼다). 그런데 이 조건이 진짜로 문서를 바꾼 모든 조건보다 성적도 좋고
라운드도 자주 아꼈다. **문서가 좋아질 수 없는 쪽이 이긴다면, 그 승패는 문서가 좋아진
효과가 아니다.** 2.3.1 절이 `d` = 0 과 `d` = 3 **양쪽**을 기준선으로 계산해,
9 개 대비가 모두 유의하지 않음을 확인한다.

**결론의 범위.** 결론은 *"재순위는 쓸모없다"* 가 아니다. 정확히는 **"이 모델
규모와 이 예산에서, 학습 라운드를 줄이는 경로만으로는 재순위 계산을 되살 수 없다"**
이다. 두 가지를 함께 읽어야 한다 — (i) 이 보고서의 비용 회계는 재순위의 배포
**비용**만 물리고 배포 **이득**(서빙 정확도)은 0 으로 둔다(2.4 절), (ii) 시드 4 개로는
`p` < 0.05 가 구조적으로 불가능하다(7.5 절). **어디서 끊기는지를 특정한 것**이 기여다.

## 1. 이 보고서가 읽는 것

4 주차가 디스크에 남긴 24 개의 학습 곡선 `results/logs/runs/*.jsonl` **뿐이다.**
재학습은 없다. 비용 가정을 바꾸거나 목표 점수를 다시 쓸어도 로그만 다시 읽는다 —
3 주차가 모든 것을 파일로 기록한 이유가 이 분리다.

## 2. 실험이 무엇을 바꿨나

### 2.1 깊이가 하는 일

모든 조건에서 **프롬프트에 들어가는 문서는 3 개**다. 바뀌는 것은 **몇 개 중에서
고르느냐**뿐이다.

| `d` | 하는 일 | 새 문서 비율 |
|---|---|---|
| 0 | 검색이 고른 3 개 그대로 | 0 % |
| **3** | **그 3 개를 다시 보고 순서만 바꿈** | **0 %** |
| 7 | 상위 7 개를 검토해 3 개 선택 | 36.2 % |
| 10 | 10 개 중 3 개 | 42.0 % |
| 25 | 25 개 중 3 개 | 49.8 % |
| 50 | 50 개 중 3 개 | 52.5 % |

"새 문서 비율" 은 프롬프트의 3 개 중 **원래 검색이라면 고르지 않았을** 문서의
비율이다. 깊이를 올릴수록 **단조로 커진다** — 처리는 설계대로 걸렸다.

**그런데 포화한다.** 깊이 10 에서 50 으로 **다섯 배** 올려도 새 문서 비율은 42 % 에서
52.5 % 로 **4 분의 1 만** 는다. 교차인코더가 올릴 만한 문서는 후보 목록 **앞쪽에
몰려 있고**, 뒤쪽을 더 뒤지는 것은 대부분 헛일이다.

> 이 포화가 뒤에서 중요해진다. **계산 비용은 깊이에 비례해 선형으로 늘어나는데,
> 그 대가로 얻는 처리 용량은 포화한다**(7 절).

### 2.2 "자리가 바뀐 것" 과 "문서가 바뀐 것" 은 다르다

프롬프트 3 개 자리를 두 가지로 센다.

| 세는 것 | 뜻 |
|---|---|
| **자리 변경** | 그 자리에 **다른 문서**가 왔는가 (순서가 바뀐 것도 포함) |
| **새 문서** | 그 문서가 **원래 검색이라면 안 골랐을** 것인가 |

둘의 차이가 중요하다.

| `d` | 자리 변경 | 새 문서 | 차이 |
|---|---|---|---|
| 3 | 45.0 % | **0 %** | **45.0 %p** |
| 7 | 64.8 % | 36.2 % | **28.6 %p** |
| 10 | 67.6 % | 42.0 % | 25.6 %p |
| 25 | 71.2 % | 49.8 % | 21.4 %p |
| 50 | 72.4 % | 52.5 % | **19.9 %p** |

**그 차이가 "원래 있던 3 개를 섞은 것" 이다.** `d` = 7 에서는 자리의 64.8 % 가
바뀌었지만 그중 새 문서는 36.2 % 뿐이고, 나머지 **28.6 %p 는 그냥 순서가 바뀐
것**이다.

그리고 깊이가 깊어질수록 이 간격이 좁아진다(45.0 → 19.9 %p). 즉:

> **얕은 깊이의 처리는 상당 부분이 순서 바꾸기이고, 깊어져야 내용 교체가 주가 된다.**

(두 값 모두 전 라운드 평균이다. 새 문서 비율은 검색 캐시가 2 주차에 얼어 있어
라운드마다 **정확히 같다** — 변한다면 그것이 결함이다.)

`d` = 3 을 통제로 둔 이유가 바로 이것이다. 자리는 45.0 % 바뀌는데 새 문서는 0 % 인
조건 — **순수하게 "순서 바꾸기" 만 하는 조건**이 있어야, 처리의 효과에서 그 성분을
빼낼 수 있다.

### 2.3 `d` = 3 — 이 측정의 자

3 개 중에서 3 개를 고르면 **그 3 개**다. 네 번째가 올라올 수 없다. 순서만 바뀐다.

```
d = 0 :  [A] [B] [C]
d = 3 :  [C] [A] [B]      <- 같은 문서, 다른 순서
d = 50:  [A] [X] [Y]      <- 새 문서가 들어옴
```

**문서가 달라질 수 없는 조건**을 일부러 넣었다. 그런데 실제로는 차이가 났다.

```
d = 3 과 d = 0 의 F1 차이  =  +0.31   (표준오차 0.37)
```

**그런데 이 +0.31 자체가 0 과 구별되지 않는다.** 표준오차가 0.37 로 값보다 크고,
`p` = 0.46 이다. 95 % 구간은 **[−0.87, +1.49]** — 참값이 0 일 수도 1.5 일 수도 있다.

> **그래서 이 0.31 을 "잡음의 크기" 라는 자로 쓰지 않는다.** 0 과 구별되지 않는 양을
> 다른 양의 기준으로 쓸 수는 없다. 저울로 비유하면, 빈 봉투를 올려 0.31 g 을 읽었는데
> 그 저울의 바늘이 혼자 ±0.37 g 흔들리는 상황이다. 알아낸 것은 봉투의 무게가 아니라
> **바늘의 흔들림**이다.

**`d` = 3 이 말해 주는 것은 따로 있다.** 이 조건은 문서는 못 바꾸지만 **순서는 바꾼다**
— 2.2 절이 `d` = 3 을 "자리만 바뀐 성분" 이라 부른 이유다. 그리고 언어모델은 같은
문서라도 놓인 순서에 반응할 수 있다(Liu et al., *Lost in the Middle*, TACL 2024).
따라서 +0.31 ± 0.37 은 **순서 효과의 추정치**이고, 그 추정치가 0 과 구별되지 않는다.
읽을 수 있는 결론은 하나다: **이 분해능에서는 순서 효과도 분해되지 않는다.**

(순서 효과의 **부호**를 이 데이터로 정할 수는 없다. 그래서 +0.31 을 "잡음의 상한"
이라고 부르지 않는다 — 순서가 점수를 깎았다면 표집 오차는 0.31 보다 **컸던** 것이고,
어느 쪽인지 알 방법이 없다.)

### 2.3.1 그럼 자는 무엇인가 — 각 비교 자신의 표준오차

**분해능은 다른 비교의 점추정치가 아니라, 그 비교 자신의 표준오차다.** 시드로 짝지어
재면 시드마다 라운드 수가 통째로 오르내리는 성분이 상쇄된다(비대응 0.879 라운드 대
대응 0.16 ~ 0.47 — 같은 데이터에서 분해능이 2 ~ 5 배 좋아진다).

**그리고 임계값은 2 가 아니다.** 시드 4 개는 자유도 3 이고, 양측 95 % 값은
**`t` = 3.182** 다. 이 보고서의 이전 판은 "표준오차의 2 배" 를 썼는데, 느슨한 쪽으로
1.6 배 틀린 규칙이었다.

```
판정 문턱  =  3.182 × (그 비교의 표준오차)  =  0.52 ~ 1.48 점
관측된 가장 큰 차이                        =  0.60 점
```

**그래서 어느 기준선을 쓰든, 아무 대비도 문턱을 넘지 못한다** (대응표본 t 검정):

| 처리 | `d` = 0 기준 | `d` = 3 기준 |
|---|---|---|
| `d` = 7 | +0.07 ± 0.16 (`p` = .685) | −0.24 ± 0.27 (`p` = .442) |
| `d` = 10 | +0.60 ± 0.28 (`p` = .127) | +0.29 ± 0.25 (`p` = .329) |
| `d` = 25 | +0.11 ± 0.47 (`p` = .825) | −0.20 ± 0.42 (`p` = .667) |
| `d` = 50 | +0.28 ± 0.31 (`p` = .437) | −0.03 ± 0.45 (`p` = .947) |

**이 표가 순서 효과 논쟁을 비켜 간다.** "`d` = 3 을 기준선으로 쓰면 순서 효과가
상쇄된다" 고 **주장하지 않는다** — 그 상쇄는 순서와 내용이 서로 얽히지 않는다는 가정을
필요로 하고, *Lost in the Middle* 이 보인 위치 효과는 **어느 문서가 어디 놓이는지**에
달려 있어 그 가정이 성립할 이유가 없다. 대신 **양쪽 기준선으로 다 계산해서 둘 다
유의하지 않음을 보인다.** 가정이 아니라 확인이다.

> **그리고 `d` = 10 의 +0.60 이 이 수정의 이유다.** 옛 규칙(2 × 표준오차 = 0.56)에서는
> 이 값이 **"유의"** 였다. 올바른 문턱은 0.91 이고 `p` = 0.127 이다. 결론의 방향은
> 바뀌지 않았지만, 규칙은 틀렸었다.

### 2.4 평가는 전 조건에서 `d` = 0 으로 고정했다

`d` = 50 으로 학습한 모델도 **채점할 때는 `d` = 0 의 문서**를 받는다. 실제로 그렇게
되었음은 로그가 확인한다 — 평가 문서의 품질이 깊이에 무관하게 소수점 셋째 자리까지
같았다.

**왜 그래야 하는가.** 재순위가 점수를 올릴 수 있는 길이 둘인데, 둘이 전혀 다르다.

| 길 | 어떻게 | 통신량과 관계 |
|---|---|---|
| **학습** | 좋은 문서로 공부 → 모델이 좋아짐 | **있음.** 모델이 좋으면 라운드가 줄고, 라운드가 곧 바이트 |
| **서빙** | 시험 때 좋은 문서를 받음 → 같은 모델로 더 나은 답 | **없음.** 질문마다 재순위를 영원히 돌려야 하고 라운드와 무관 |

각 조건을 자기 깊이에서 채점했다면 두 길이 **더해져서 구분되지 않는다.** `d` = 50 이
높은 점수를 받아도 **모델이 좋아져서인지 시험 때 좋은 문서를 받아서인지** 알 수 없다.

그리고 서빙 쪽은 거의 확실히 점수를 올린다 — 2 주차에서 `d` = 50 의 문서 품질이
`d` = 0 보다 3.92 %p 높았다. **그 이득을 섞어 넣었다면 이 보고서는 "재순위가 통신량을
줄인다" 는 결론을 만들어냈을 것이다.** 실제로 줄인 것은 없는데도.

**대가와 그 처리.** 그래서 보고되는 점수는 실제 배치 시스템보다 낮다. 의도된 것이다.

**다만 분명히 해 둘 것이 있다. 서빙 이득은 장부에 올라가지 않는다.** 5 절과 6 절은
재순위의 배포 **비용**(질문당 계산량)을 물리지만, 재순위의 배포 **이득**(더 나은
답)은 0 으로 둔다. 이 실험이 그것을 측정하지 않았기 때문이다.

> **즉 이 보고서의 회계는 한쪽만 올린 것이고, 재순위에 불리한 방향으로 편향되어
> 있다.** 6 절이 이 편향의 크기를 다루고, 9 절이 그것을 한계로 기록한다. 결론을
> 읽을 때 반드시 함께 읽어야 한다 — 이 보고서가 말할 수 있는 것은 **"학습 라운드를
> 줄이는 경로만으로는 되살 수 없다"** 이고, **"재순위가 경제성이 없다" 는 아니다.**

## 3. 라운드를 몇 번 덜 썼나

### 3.1 재는 방법

통신량은 라운드에 비례한다(**라운드 1 회 = 29.5 MB**). 그래서 "얼마나 아꼈나" 는
"몇 라운드 덜 썼나" 와 같은 질문이다.

목표 점수를 정하고, 각 조건이 **몇 번째 라운드에 그 점수에 도달했는지** 세어 기준선과
비교한다.

```
기준선(d=0) 도달 라운드  −  해당 깊이 도달 라운드
      양수 → 덜 썼다 (이득)        음수 → 더 썼다 (손해)
```

도달 라운드는 평가 지점 사이를 직선으로 이어 읽는다. LoRA 는 몇 라운드 만에
수렴하므로 "9 라운드" 같은 정수로는 9 와 10 사이가 통째로 사라지고, 조건 간 차이는 그
안에 들어가기 때문이다.

### 3.2 목표 점수를 정하는 법 — 고르지 않는다

목표를 하나 고르면 그 선택이 결론을 정한다. 실제로 그 위험이 현실이 된 적이 있다:
목표 25.02 점 한 곳에서는 `d` = 25 만 이득이었고, 그 한 값이 판정을 뒤집었다. 전체로
보면 같은 깊이가 손해다.

그래서 목표를 **고르지 않고, 기준선이 실제로 받은 점수를 전부 쓴다.**

**80 이 나오는 곳.** 기준선 `d` = 0 을 시드 4 개로 돌렸고, 각 run 은 정해진 20 개
라운드에서 평가한다(라운드 1 ~ 10, 그 뒤 5 라운드마다, 마지막 59).

```
4 run × 20 회 평가  =  점수 80 개      <- 목표 후보 전부
```

이 80 개가 **실제로 측정된 점수**다. 임의 간격의 격자가 아니다.

**18.13 — 아래 경계.** 네 시드가 **라운드 1 에서** 받은 점수를 본다.

| 시드 | 라운드 1 점수 |
|---|---|
| 1 | **18.13** |
| 2 | 17.38 |
| 3 | 17.89 |
| 4 | 17.15 |

그중 **가장 높은 18.13** 이 경계다. 목표를 그보다 낮게 — 예를 들어 17.50 으로 —
잡으면 시드 1 은 라운드 1 에 이미 18.13 이므로 **1 라운드에 도달**하고, 시드 3 도
마찬가지다. 전 조건이 1 라운드에 도달해 **비교할 것이 없어진다.** 18.13 은 **네 시드
모두가 라운드 1 을 넘겨야 도달하는 가장 낮은 점수**다.

**28.14 — 위 경계.** 네 시드가 59 라운드를 다 써서 받은 **최고점**을 본다.

| 시드 | 최고점 |
|---|---|
| 1 | 28.44 |
| 2 | 29.92 |
| 3 | **28.14** |
| 4 | 30.66 |

그중 **가장 낮은 28.14** 가 경계다. 목표를 그보다 높게 — 예를 들어 29.00 으로 —
잡으면 시드 3 은 최고가 28.14 라서 **끝까지 가도 도달하지 못한다.** 네 시드 중 둘만
값이 생겨 평균을 낼 수 없다. 28.14 는 **네 시드 모두가 도달할 수 있는 가장 높은
점수**다.

**17 — 빠지는 개수.** 80 개 중 두 경계 바깥이 17 개다.

| 빼는 것 | 몇 개 | 어떤 값인가 |
|---|---|---|
| 18.13 미만 | **3 개** | 17.15, 17.38, 17.89 — 시드 2 · 3 · 4 의 라운드 1 점수 |
| 28.14 초과 | **14 개** | 28.44 ~ 30.66 — 주로 시드 2 와 4 의 후반 라운드 점수 |

```
80 − 3 − 14  =  63 개
```

**두 경계도 데이터가 정했다.** 아래는 네 시드의 라운드 1 점수 중 최대, 위는 네 시드
최고점 중 최소다. **이 절에 임의로 정한 숫자가 하나도 없다.**

### 3.3 결과

63 개 목표 각각에서 승패를 매기고 세었다.

| `d` | 기준선을 이긴 목표 | 그중 **문턱을 넘은 것** | 보통 (중앙값) |
|---|---|---|---|
| **3** *(통제)* | **41 / 63** | **5 / 63** | **0.15 라운드 빠름** |
| 7 | 19 / 63 | 0 / 63 | 0.56 라운드 느림 |
| 10 | 20 / 63 | 1 / 63 | 0.21 라운드 느림 |
| 25 | 24 / 63 | 1 / 63 | 0.11 라운드 느림 |
| 50 | 15 / 63 | 5 / 63 | 0.37 라운드 느림 |

**"문턱을 넘은 것"** — 2.3.1 절의 판정 문턱, 즉 **그 차이 자신의 표준오차 × 3.182**
를 넘은 목표의 수다. 시드 4 개면 자유도 3 이고 양측 95 % 값이 3.182 다.

이 보고서의 이전 판은 이 열을 **표준오차 1 배**로 세어 26 / 10 / 16 / 9 / 7 을 적었다.
그 규칙은 "확실한 승리" 라고 부를 수 없는 것들을 세고 있었다. 올바른 문턱에서는
**어느 조건도 63 개 중 5 개를 넘지 못한다.**

**"보통"** — 63 개를 줄 세운 **한가운데 값**이다. 평균이 아닌 이유는, 목표를 높게
잡으면 곡선이 평평해져(25.02 점에 9 라운드, 28.14 점에 38.7 라운드) 작은 점수 차이가
라운드 10 개로 번역되고 값이 ±11 까지 튀기 때문이다. 그 구간을 **잘라내지는 않았다** —
어디서 자를지가 또 임의 선택이 되므로, 대신 극단값에 흔들리지 않는 통계를 썼다.

### 3.4 이 표가 말하는 것

**통제가 1 위다.** `d` = 3 은 문서를 바꿀 수 없는데 63 개 중 41 개를 이겼다. 진짜로
문서를 바꾼 네 조건은 15 ~ 24 개에 그치고 **보통은 전부 느리다.**

**효과가 전혀 없다면 승률이 약 50 %, 즉 31 / 63 쯤 나와야 한다.** 통제만 그보다
위(41)이고, 문서를 바꾼 네 조건은 **전부 그보다 아래**다(15 ~ 24).

**그리고 어느 조건도 문턱을 넘은 목표가 과반이 아니다** — 최대가 5 / 63 이다. 즉
승패의 분포 자체가 동전 던지기와 구별되지 않는다.

> 문서가 좋아질 수 없는 조건이 가장 자주 이긴다면, 그 승패는 **문서가 좋아진
> 효과가 아니다** — 순서 효과이거나 측정의 흔들림이다. 둘 중 무엇이든, 깊이를 올려
> 문서를 바꾼 대가로 얻은 것은 아니다.

### 3.5 보간을 쓰지 않는 두 번째 확인

3.3 절의 도달 라운드는 평가 지점 **사이를 이어 읽은 값**이다. 그 읽는 방식 자체가
의심받을 수 있으므로, 전혀 다른 축을 고정해 한 번 더 확인했다.

**방법.** 모든 조건이 같은 라운드에 같은 바이트를 쓴다. 그러므로 **라운드 N 은 예산이
똑같은 지점**이다. 거기서 점수만 직접 비교하면 보간이 필요 없다.

| | 3.3 절 | 3.5 절 |
|---|---|---|
| 고정하는 것 | **점수** (목표) | **예산** (라운드 = 바이트) |
| 비교하는 것 | 도달 **라운드** | 그 시점의 **점수** |
| 보간 | 필요 | **불필요** |
| 지점 수 | 목표 63 개 | 평가 라운드 20 개 |

**한 지점을 끝까지 계산하면.** 라운드 1 — 두 조건이 똑같이 29.5 MB 를 쓴 시점이다.

| 시드 | `d` = 0 | `d` = 3 | 차이 |
|---|---|---|---|
| 1 | 18.13 | 18.71 | +0.58 |
| 2 | 17.38 | 17.65 | +0.27 |
| 3 | 17.89 | 18.50 | +0.62 |
| 4 | 17.15 | 17.51 | +0.36 |
| | | **평균** | **+0.458** |
| | | **오차** | **0.084** |

**"0 과 구별된다"** 는 `|평균| > 2 × 오차` 일 때를 말한다.

```
|0.458|  >  2 × 0.084 = 0.168      ->  구별됨
```

네 시드가 **한 방향으로 일관되게** 차이를 보였다는 뜻이다(+0.27 ~ +0.62 로 모여
있다). 반대로 라운드 2 에서 `d` = 3 은 +0.084 ± 0.213 이었다 — 차이보다 오차가 커서
구별되지 않는다. 2 배를 기준으로 삼은 것은 통계의 관례로, 진짜 차이가 0 인데 우연히
이만큼 나올 확률이 약 5 % 이하가 되는 지점이다.

**20 개 지점에서 이 판정을 세면:**

| `d` | 차이가 0 과 구별된 지점 |
|---|---|
| **3** *(통제)* | **8 / 20** |
| 7 | 4 / 20 |
| 10 | **8 / 20** |
| 25 | 5 / 20 |
| 50 | 6 / 20 |

**통제가 `d` = 10 과 같은 횟수이고, 나머지 세 처리보다 많다.** 보간을 전혀 쓰지 않는
방법에서도 3.4 절과 같은 결론이 나온다 — 두 방법이 서로 다른 축을 고정하는데도 같은
답을 낸다.

## 4. 계산을 얼마나 썼나

비용은 두 항이다.

```
일회성   인덱싱    = 코퍼스 전체를 한 번 임베딩
반복     재순위    = Q × 깊이 × 쌍당 계산량
```

### 4.1 `Q` 가 무엇인가 — 두 개의 다른 질문

`Q` 는 **재순위를 돌려야 하는 질문의 개수**다. 질문 하나가 들어오면 교차인코더가
후보 `d` 개를 하나씩 채점하므로, 총 채점 횟수가 `Q × d` 쌍이다.

**그런데 `Q` 에 들어갈 수 있는 숫자가 두 개이고, 둘은 다른 질문에 답한다.**

| | 값 | 어떤 질문에 답하나 |
|---|---|---|
| **① 실측** | **80,720** | *"이 실험이 쓴 계산이 본전이었나"* |
| **② 선언** | **10³ ~ 10⁷** | *"이걸 배포하면 본전이 되나"* |

**①은 쟀다.** 게이트 3 이 고정한 클라이언트당 10,090 질문 × 8 클라이언트다.
재순위 점수는 2 주차에 캐시로 얼렸으므로 **질문당 한 번**만 수행되었다(캐시가
없었다면 패스 수만큼, 즉 1.5 배였고 부호는 같다).

**②는 잴 수 없다.** 배포 후의 값이고 이 실험은 배포해 본 적이 없다. 같은 시스템을
병원에 깔면 하루 수백 질문이고 검색 서비스면 수백만이다. 그래서 하나 고르지 않고
자릿수를 덮어 쓸어 본다.

> **두 회계를 모두 보고한다.** 이 보고서의 이전 판은 `Q` 에 선언값만 넣고 그 사실을
> 4 절에 적지 않았다 — 식에 정의 없는 기호가 하나 있었고, 그 기호가 결론을
> 좌우했다(`손익분기 대역폭 ∝ 1/Q`). 그러면 "고르기만 하면 원하는 답이 나오는
> 것 아닌가" 라는 물음에 답할 수 없다. 5 절과 6 절이 두 값에서의 결과를 나란히
> 적고, **둘이 같은 답을 낸다.**

**빼놓은 항도 적어 둔다.** 질의 임베딩 비용은 깊이와 무관하므로 조건을 가르지 못해
뺐다(인덱싱과 같은 논리). 상위 `d` 개를 색인에서 꺼내는 ANN 검색 비용은 깊이에 따라
늘지만 선형 이하이고, **이것만은 빼는 쪽이 보수적이지 않다** — 이 모델이 실제 비용을
과소평가하는 유일한 항이고, 그 방향은 결론을 더 강하게 만든다.

**쌍당 계산량도 조건이 붙는다.** 5.437 × 10⁹ 은 **256 토큰으로 패딩한 조건의
실측**이고, 실제 문서 길이의 평균이 아니다. 패딩 없이 재면 3.9 배 작아져 분모가
그만큼 줄고 손익분기 대역폭이 커진다 — **256 을 쓰는 쪽이 재순위에 불리하므로
보수적이다.**

| `d` | 질문 1 개당 계산 | 이 CPU 에서 |
|---|---|---|
| 3 | 1.63 × 10¹⁰ FLOPs | 0.15 초 |
| 7 | 3.81 × 10¹⁰ | 0.34 초 |
| 10 | 5.44 × 10¹⁰ | 0.49 초 |
| 25 | 1.36 × 10¹¹ | 1.23 초 |
| 50 | 2.72 × 10¹¹ | **2.46 초** |

깊이에 **정비례**한다. 쌍당 계산량은 4 주차에서 실측했다(해석적 추정과 2 배 이내로
일치).

**일회성 항은 조건을 가르지 못한다.** 깊이와 무관하게 같은 값이기 때문이다. 이것이
**재순위 깊이를 처리 축으로 삼은 이유**다 — 깊이는 질문당 **반복** 비용이라, 라운드당
통신량과 같은 단위에서 맞바꿀 수 있다.

두 가정을 **모두** 보고한다. 어느 쪽이 맞는지는 배치 상황이 정하므로 고르지 않는다.

| 가정 | 뜻 |
|---|---|
| `amortised` | RAG 가 이미 배치되어 인덱스가 존재 → 일회성 항 0 |
| `with_indexing` | 이 학습을 위해 인덱스를 새로 구축 → 일회성 항 부과 |

## 5. 환율 — 아낀 바이트를 쓴 계산량으로 나눈 값

```
환율 = 아낀 바이트 ÷ 더 쓴 계산량
```

**대역폭도 장치 속도도 들어가지 않는다.** 그 둘은 6 절에서 곱해진다. 특정 배치의
결론은 이 숫자에 그 배치의 값을 곱한 것이다.

**다만 `Q` 는 들어간다. 그리고 그것이 이 값의 성격을 정한다.**

```
분자  아낀 바이트     =  학습할 때 **한 번** 생긴다
분모  재순위 계산량   =  배포 후 Q 개 질문에 대해 쌓인다
```

**둘은 다른 시점의 양이다.** 그래서 이 값은 "1 FLOP 으로 몇 바이트를 산다" 는
비율이 아니라 **"일회성 이득 ÷ 평생 비용"** 이고, **평생 길이(`Q`)를 정하는 사람이
값을 정한다.** 단일 숫자가 아니라 `Q` 의 함수다 — 크기가 `1/Q` 로 줄어든다.

그래서 아래 표에 **`Q` 를 명시하고**, 4.1 절의 두 값에서 **모두** 적는다.

**부호는 `Q` 와 무관하다.** 분모가 항상 양수이므로 부호는 아낀 바이트의 부호 그대로다:

| 질문 수 | `d` = 50 의 환율 | 부호 |
|---|---|---|
| 1,000 | −4.054 × 10⁻⁸ | 음수 |
| 100,000 | −4.054 × 10⁻¹⁰ | 음수 |
| 10,000,000 | −4.054 × 10⁻¹² | 음수 |

**결론은 질문 수를 어떻게 잡아도 같다.**

**분자는 3.3 절과 같은 통계다 — 63 개 목표의 중앙값**에 라운드당 통신량
(29.49 MB)을 곱한 값이다.

| `d` | 아낀 바이트 | 환율 (인덱스 있음) | 환율 (인덱스 구축) |
|---|---|---|---|
| **3** *(통제)* | **+4.41 MB** | **+2.70 × 10⁻⁹** | **+1.62 × 10⁻⁹** |
| 7 | −16.52 MB | −4.34 × 10⁻⁹ | −3.38 × 10⁻⁹ |
| 10 | −6.27 MB | −1.15 × 10⁻⁹ | −9.61 × 10⁻¹⁰ |
| 25 | −3.32 MB | −2.45 × 10⁻¹⁰ | −2.26 × 10⁻¹⁰ |
| 50 | −11.02 MB | −4.05 × 10⁻¹⁰ | −3.90 × 10⁻¹⁰ |

*(환율은 `Q` = 100,000. 산출물의 `exchange_rate_query_volume` 에 기록된다.)*

**음수는 "계산을 쓰고 바이트도 더 썼다" 는 뜻이다. 열 칸 중 여덟 칸이 음수이고,
양수인 두 칸은 둘 다 통제 `d` = 3 이다.**

> **진짜로 문서를 바꾼 네 조건은 전부 음수다.** 유일하게 바이트를 아낀 조건이
> **문서가 좋아질 수 없는 조건**이라면, 그 절약은 문서가 좋아진 대가가 아니다.

**이 표는 이전 판과 부호가 다르다.** 이전 판은 분자를 **대표 tau 한 점**
(τ = 25.0185)에서 읽었고, 그 결과 `d` = 3 이 −17.8 MB, `d` = 25 가 +2.9 MB 로
**3.3 절의 중앙값과 부호가 반대**였다. 두 표가 다른 통계를 쓰고 있었다. 이제 둘이
같은 통계를 쓴다.

### 5.1 인덱싱 가정이 부호를 바꿀 수 **없는** 이유

```
환율 = 아낀 바이트 ÷ (재순위 FLOPs + 인덱싱 FLOPs)
                      └── 양수 ──┘   └── 양수 ──┘
                            분모 = 항상 양수
```

**부호는 분자만으로 결정된다.** 인덱싱 FLOPs(1.09 × 10¹⁵)는 양수이고 분모에
더해지므로, 이 가정은 **구조적으로** 방향을 바꿀 수 없다.

이 보고서의 이전 판은 *"두 가정의 부호가 모든 깊이에서 일치한다"* 를 강건성 검증으로
제시했다. **그것은 검증이 아니라 산수였다** — 분자가 열 칸 모두 동일하고 분모만
바뀌었으니 다른 결과가 나올 수 없었다.

**결론이 인덱스 보유 여부에 의존하지 않는다는 것은 여전히 참이다.** 다만 그 근거는
데이터가 아니라 **식의 구조**다. 데이터는 바뀔 수 있지만 구조는 바뀌지 않으므로,
이쪽이 더 강한 근거다.

두 가정이 실제로 바꾸는 것은 **크기**이고, 그 차이가 위 표의 두 열이다. 손익분기
대역폭에서의 차이는 6 절에서 다룬다.

### 5.2 실측 `Q` 에서도 같은 답이 나온다

4.1 절의 두 회계를 나란히 놓는다.

| `d` | 아낀 바이트 | `B*` (실측 `Q` = 80,720) | `B*` (배포 `Q` = 100,000) |
|---|---|---|---|
| **3** *(통제)* | +4.41 MB | **0.0268 Mbps** | **0.0216 Mbps** |
| 7 | −16.52 MB | 0 | 0 |
| 10 | −6.27 MB | 0 | 0 |
| 25 | −3.32 MB | 0 | 0 |
| 50 | −11.02 MB | 0 | 0 |

**80,720 과 100,000 이 24 % 차이밖에 나지 않아 두 회계가 같은 답을 낸다.** 즉 이
결론은 `Q` 를 "실험이 쓴 양" 으로 읽든 "배포하면 쓸 양" 으로 읽든 바뀌지 않는다.

그리고 **0 이 아닌 유일한 칸이 통제**다. 그 구간이 어디에 있는지는 6 절에서 본다.

## 6. 손익분기 — 어떤 링크에서 이득인가

5 절의 환율은 "바이트 ÷ 계산량" 이라 단위가 서로 다른 둘의 비율이다. 실제 배치에서
이득인지 손해인지 말하려면 둘을 **같은 단위**로 바꿔야 한다. 그 단위가 **초**다.

```
아낀 전송 시간  =  아낀 바이트 × 8 ÷ 대역폭        (비트를 링크로 보내는 시간)
더 쓴 계산 시간 =  총 계산량 ÷ 장치 속도            (재순위를 돌리는 시간)
```

둘이 같아지는 대역폭이 **손익분기 대역폭**이다.

```
아낀 바이트 × 8 ÷ B*  =  계산량 ÷ 장치속도
            B*  =  아낀 바이트 × 8 × 장치속도 ÷ 계산량
```

**이 `B*` 보다 느린 링크에서는 재순위가 이득이다.** 링크가 느릴수록 바이트 하나를
보내는 데 오래 걸리고, 그만큼 아낀 바이트의 가치가 커지기 때문이다. 반대로 아주 빠른
링크에서는 바이트가 싸서 계산을 더 쓸 이유가 없다.

### 질문 수와 대역폭은 **선언한 값**이다

여기서 한 가지를 분명히 해 둔다. 3.2 절의 목표 점수 τ 는 **데이터가 정했다** —
기준선 곡선이 실제로 지나간 점이고, 두 경계도 유도된다. 반면 **질문 수와 대역폭은
설정에 선언한 값**이다.

유도할 수 없기 때문이다. 둘 다 **아직 일어나지 않은 배치**에 관한 값이다. 같은
시스템을 병원에 깔면 하루 수백 질문이고 검색 서비스면 수백만이다. 이 실험이 알 수
있는 것이 아니다.

그래서 **하나 고르지 않고 쓸어서 곡면으로 보고한다** — 고르지 않는다는 점에서 τ 와
같은 원칙이다. 범위는 로그 간격으로 자릿수를 덮는다.

| 축 | 범위 | 양 끝이 뜻하는 것 |
|---|---|---|
| 대역폭 | 1 ~ 1,000 Mbps | 제약된 링크 ~ 데이터센터 |
| 질문 수 | 10³ ~ 10⁷ | 소규모 파일럿 ~ 대규모 운영 |

**그리고 부호는 그 범위에 의존하지 않는다.** 질문 수를 만 배 바꿔도 손익분기
대역폭의 **부호가 바뀌지 않는다** — 분자인 아낀 바이트가 질문 수와 무관하기
때문이다. 아낀 바이트가 음수인 **문서를 바꾼 네 깊이**에서는 `B*` 가 질문 수와
무관하게 0 이고, 유일하게 양수인 **통제 `d` = 3** 에서는 `B*` 가 질문 수와 무관하게
양수다. 범위를 어떻게 잡아도 어느 깊이가 어느 쪽인지가 바뀌지 않는다.

### 질문 수가 왜 축인가

**질문 수** `Q` 는 배포 후 이 시스템이 처리할 질문의 수다(4.1 절). 재순위는 배치된
뒤 **질문마다** 돌아간다.

```
총 계산량  =  Q × 깊이 × 쌍당 계산량
```

반면 **아낀 바이트는 학습 때 한 번 생기고 끝난다.** 그래서 질문이 쌓일수록 분모만
커지고 분자는 그대로다 — `B*` 가 `1/Q` 로 내려간다.

### 이 회계가 결론에 미치는 영향 — 반드시 먼저 읽을 것

**`Q` 를 충분히 크게 잡으면 일회성 절약은 어떤 방법이든 본전이 될 수 없다.**

```
Q = 10³    ->  B* = 2.2 × 10⁰   Mbps   (d = 3)
Q = 10⁷    ->  B* = 2.2 × 10⁻⁴
Q = 10¹²   ->  B* = 2.2 × 10⁻⁹         ->  0 으로 수렴
```

**즉 "운영 구간이 없다" 는 결론의 일부는 발견이 아니라 회계 방식의 결과다.** 분자는
고정이고 분모는 `Q` 와 함께 무한히 커지기 때문이다.

그리고 2.4 절이 적었듯 **이 회계는 비용만 물리고 이득은 물리지 않는다.** 배포 시
재순위를 돌리면 답도 더 정확해지는데(2 주차에서 `d` = 50 의 문서 품질이 `d` = 0 보다
3.92 %p 높았다), 그 이득은 장부에 없다. 평가를 `d` = 0 으로 고정했기 때문이다.

> **그래서 이 절의 결론은 이렇게만 읽어야 한다.**
>
> **"학습 라운드를 줄이는 경로 하나만으로는 재순위 비용을 되살 수 없다."**
>
> **"재순위가 경제성이 없다" 가 아니다.** 그 판단에는 서빙 이득이 필요하고, 이
> 실험은 그것을 측정하지 않았다. 9 절에 한계로 기록한다.

이 범위 안에서는 결론이 선언값에 의존하지 않는다 — `Q` 는 크기만 바꾸고 **부호를
바꾸지 못한다.**

### 측정 결과 — `d` = 50

| 질문 수 `Q` | 손익분기 대역폭 (`d` = 50) |
|---|---|
| 1,000 | **0 Mbps** |
| 10,000 | 0 Mbps |
| 100,000 | 0 Mbps |
| 1,000,000 | 0 Mbps |
| 10,000,000 | 0 Mbps |

**0 은 "그런 링크가 없다" 는 뜻이다.** 아낀 바이트가 음수이므로 위 식의 `B*` 도
음수가 되는데, 음수 대역폭은 존재하지 않는다. 그래서 0 으로 보고한다.

**다섯 줄이 전부 0 인 것이 중요하다.** 총 계산량은 질문 수에 정확히 비례해
2.72 × 10¹⁴ 에서 2.72 × 10¹⁸ 까지 **만 배** 커지는데, `B*` 는 전부 0 이다. 분자인
아낀 바이트가 음수인 한 **질문 수가 무엇이든 부호가 바뀌지 않기** 때문이다. 즉 이
결론은 위에서 선언한 범위에 **의존하지 않는다.**

보통 이 표는 *"1,000 질문이면 1.85 Mbps 이하에서 이득, 100 만 질문이면 0.002 Mbps
이하"* 처럼 읽히고, 결론이 **"아주 느린 링크 + 적은 질문 수" 라는 좁은 구석**으로
좁혀진다. `d` = 50 에서는 그 구석조차 없다 — 아무리 느린 링크에서도 이득이 아니다.
**문서를 실제로 바꾼 네 조건(`d` = 7, 10, 25, 50)이 모두 이와 같다.** 아낀 바이트가
전부 음수이므로 다섯 줄이 전부 0 이다.

### 0 이 아닌 조건이 하나 있다 — 그리고 그것이 통제다

5 절에서 유일하게 양수였던 조건은 **통제 `d` = 3** (+4.41 MB)이다. 여기서도 **0 이
아닌 `B*`** 를 낸다. 숨기지 않고 적는다.

| 질문 수 `Q` | `B*` (인덱스 있음) | `B*` (인덱스 구축) |
|---|---|---|
| 1,000 | **2.161 Mbps** | 0.032 Mbps |
| 10,000 | 0.216 Mbps | 0.028 Mbps |
| 100,000 | 0.0216 Mbps | 0.013 Mbps |
| 1,000,000 | 0.0022 Mbps | 0.0020 Mbps |
| 10,000,000 | 0.00022 Mbps | 0.00022 Mbps |

**그리고 가장 유리한 칸(2.161 Mbps)은 선언한 대역폭 범위 1 ~ 1,000 Mbps 안에 있다.**
즉 "질문 1,000 개 규모의 파일럿을 2 Mbps 보다 느린 링크로 운영한다" 면 수학적으로는
본전이 된다.

> **그런데 그 조건은 `d` = 3 — 문서를 바꿀 수 없는 조건이다.**
>
> 3 개 중에서 3 개를 고르는 것이므로 새 문서가 올라올 수 없다(2.1 절). 배포할 만한
> 처리가 아니다. **되살 수 있는 유일한 조건이 아무것도 검색하지 않는 조건이라면,
> 되산 것은 검색이 아니다.**

**문서를 실제로 바꾼 네 조건에는 그런 칸이 하나도 없다.** `d` = 7, 10, 25, 50 은
대역폭 × 질문 수 격자 40 칸 전부에서 0 이다.

> 그래서 결론은 이렇게 적는다. **문서를 바꾼 어느 깊이에서도, 어떤 링크·어떤 질문
> 수에서도 이득이 아니다. 유일하게 이득 구간을 가진 조건은 문서를 바꾸지 않는
> 통제이고, 그것은 배포 대상이 아니다.** (그리고 이 판정 자체가 위에서 적은
> 한쪽만 올린 회계 안에서의 판정이다.)

## 7. 가설의 사슬은 어디서 끊겼나

### 7.1 제안했던 경로

```
깊이 ↑ → 문서 품질 ↑ → 클라이언트가 같은 과제를 배움
       → 업데이트 발산 ↓ → 필요 라운드 ↓
```

가운데 "클라이언트가 서로 얼마나 다른 방향으로 학습하는가" 를 **발산**이라 한다.
8 개가 제각각이면 서버가 평균 내기 어렵고, 그래서 라운드가 더 필요하다는 것이
가설이었다.

### 7.2 발산은 거의 움직이지 않았다

표의 두 열이 무엇인지 먼저 밝힌다.

| 열 | 무엇을 재나 | 왜 이것을 쓰나 |
|---|---|---|
| **처리 강도** | 프롬프트 3 자리 중 **다른 문서가 온 자리의 비율** (2.2 절의 "자리 변경") | 깊이 `d` 자체는 **얼마나 뒤졌나**일 뿐, 실제로 프롬프트가 얼마나 달라졌는지를 재지 않는다. `d` 를 두 배로 해도 바뀐 자리가 그대로면 처리는 강해지지 않은 것이다 |
| **발산** | 클라이언트 8 개의 업데이트가 **서로 얼마나 다른 방향인가** | 가설의 가운데 고리. 같은 과제를 배우면 비슷한 방향으로 움직여야 한다 |

가설대로라면 **처리 강도가 커질수록 발산이 작아져야** 한다.

| `d` | 처리 강도 | 발산 |
|---|---|---|
| 0 | 0.00 | 1.3234 |
| 3 | 0.45 | 1.3218 |
| 7 | 0.65 | 1.3143 |
| 10 | 0.68 | 1.3151 |
| 25 | 0.71 | 1.3162 |
| 50 | 0.72 | **1.3132** |

처리 강도는 0 에서 0.72 로 **크게** 바뀌었는데, 발산은 1.3234 에서 1.3132 까지
**0.77 % 만** 움직였다. 그리고 깊이 순서대로 줄어들지도 않는다 — `d` = 7 이 `d` = 10
이나 `d` = 25 보다 낮다.

(발산은 학습 **초반 10 라운드**의 평균이다. 처리가 학습 방향에 영향을 준다면 가장
먼저 드러날 구간이기 때문이다.)

### 7.3 상관계수를 그대로 읽으면 안 된다

```
처리 강도 ↔ 발산 감소     +0.91
발산 감소 ↔ 라운드 절약   −0.88
```

**첫 줄만 보면 가설이 지지되는 것처럼 보인다.** 이 보고서에서 가장 오해하기 쉬운
숫자이므로 둘을 함께 읽어야 한다.

**(i) 거의 움직이지 않는 양들 사이의 상관이다.** 0.77 % 변동이다. 상관계수는 방향만
말하고 크기를 말하지 않는다.

**(ii) 다음 고리의 부호가 반대다.** 가설은 *"발산이 줄면 라운드가 준다"* 이므로
**양수**여야 하는데 **−0.88** 이다. 발산이 가장 많이 줄어든 깊이들이 라운드를 가장
많이 **더** 썼다.

> 앞 고리는 **변화량이 측정 불가 수준**이고, 뒤 고리는 **부호가 반대**다. 제안된
> 경로는 지지되지 않는다.

### 7.4 판정

```
within_noise — 가장 큰 절약은 d = 3 (통제)의 0.15 라운드이고, 63 개 목표 중
               5 개에서만 판정 문턱을 넘는다. 어떤 깊이도 과반의 목표에서
               절약을 분해하지 못한다.
```

판정 규칙은 한 줄이다 — **절약이 2.3.1 절의 문턱(표준오차 × 3.182)을 넘는 목표가
과반(63 중 32 이상)이어야 "절약이 관측되었다" 고 한다.** 어느 한 점도 판정을 뒤집을
수 없다.

### 7.5 이 설계가 분해할 수 있는 것의 한계

**`within_noise` 는 "효과를 못 찾았다" 는 변명이 아니다. 이 설계가 낼 수 있는 유일한
결과다.** 숫자로 적을 수 있다.

분포 가정을 쓰지 않는 **대응 치환검정**을 생각해 보자. 대응 설계에서 치환은 시드별
차이의 부호를 뒤집는 것뿐이므로, 가능한 배열이 `2⁴ = 16` 가지다. 가장 극단적인 결과
(네 시드 모두 같은 부호)의 양측 `p` 는 **2 / 16 = 0.125** 다.

```
시드  4 개 (현재)  ->  낼 수 있는 최소 p = 0.125    p < 0.05  불가능
시드  6 개         ->                      0.031    가능
시드  8 개         ->                      0.008    가능
```

> **시드 4 개로는 데이터가 아무리 깨끗해도 `p < 0.05` 가 구조적으로 불가능하다.**
> 그리고 이 실험에서 관측된 최소 `p` 가 **0.127** 로, 사실상 그 바닥에 붙어 있다.

**검정력으로 봐도 같다.** 80 % 검정력으로 잡으려면 효과가 **0.67 ~ 1.96 점**이어야
하는데, 관측된 효과는 **0.03 ~ 0.60 점**이다. 애초에 잡을 수 없는 크기였다.

그래서 이 절의 판정은 이렇게 읽어야 한다 — **"효과가 없다" 가 아니라 "이 설계는 어떤
효과도 유의하게 만들 수 없고, 시드 6 개부터 가능해진다" 이다.** 무엇을 바꿔야 하는지가
결론에 함께 들어 있다.

## 8. 깊이별 절충

네 축을 한자리에 놓으면 모양이 보인다.

| `d` | 질문당 계산 | 새 문서 비율 | F1 (통제 대비) | 라운드 절약 |
|---|---|---|---|---|
| **0** | 0 초 | 0 % | −0.31 | — |
| **3** *(통제)* | 0.15 초 | 0 % | — | +0.15 |
| **7** | 0.34 초 | 36 % | −0.24 | −0.56 |
| **10** | 0.49 초 | 42 % | +0.29 | −0.21 |
| **25** | 1.23 초 | 50 % | −0.20 | −0.11 |
| **50** | 2.46 초 | 53 % | −0.03 | −0.37 |

**(a) 깊이를 올리면 일관되게 좋아지는가 — 아니다.** 통제 대비 F1 은 −0.24, +0.29,
−0.20, −0.03 으로 **부호조차 일정하지 않고**, 라운드 절약은 네 처리 모두 음수다.

**(b) 수확 체감은 어디서 나타나는가 — 성능이 아니라 문서 품질에서.** 성능에는 체감할
이득 자체가 없다. 체감은 2.1 절에서 보았다 — 깊이를 다섯 배 올려도 새 문서 비율은
4 분의 1 만 는다. 그런데 **계산은 깊이에 정비례해 늘어난다**(0.34 → 2.46 초, **7 배**).
비용은 선형, 효과는 포화. 꺾이는 지점은 `d` = 10 과 `d` = 25 사이다.

**(c) 최선의 절충 깊이는 — `d` = 0.** 어떤 깊이도 지불한 계산만큼을 돌려주지 못한다.
`d` = 50 은 질문마다 2.46 초를 영구적으로 쓰면서 통신량을 **11.0 MB 더** 쓴다
(5 절, 63 개 목표 중앙값 기준).

**(d) 다만 (a)~(c) 가 어떤 회계 안에서의 판단인지 — 2.4 절과 6 절.** 이 표의 "질문당
계산" 은 재순위의 배포 비용이고, 재순위의 배포 이득(서빙 정확도)은 0 으로 두었다.
그래서 이 절이 말하는 것은 **"학습 라운드를 줄이는 경로만으로는 이 계산을 정당화할
수 없다"** 이고, "재순위를 쓰면 안 된다" 가 아니다.

## 9. 이 결론이 서는 조건

결론은 *"재순위가 쓸모없다"* 가 아니라 *"이 조건에서 재순위가 통신량을 되사지
못한다"* 이다. 조건을 밝힌다.

| 한계 | 내용 |
|---|---|
| **모델이 작다** | SmolLM2-135M 하나. 더 좋은 문서를 활용할 능력이 부족한 크기일 수 있다 |
| **시드가 4 개** | 측정이 ±0.16 ~ ±0.47 점 흔들린다. 0.3 점 효과를 가르려면 시드 16 개 = 64 run = 90 시간이 필요하다 |
| **곡선이 수렴하지 않았다** | 59 라운드로 고정했는데 대부분의 곡선이 라운드 50 이후에 최고점을 가진다 |
| **깊이 6 단** | 5 · 20 · 30 은 측정하지 않았다. 관측된 효과(0.03 ~ 0.60 점)가 전부 이 설계의 판정 문턱(0.52 ~ 1.48 점) 아래에 있어, 사다리를 촘촘히 해도 최소 눈금보다 작은 양은 읽을 수 없기 때문이다 |
| **통제가 순서를 바꾼다** | `d` = 3 은 문서는 못 바꾸지만 순서는 바꾼다. 그 +0.31 ± 0.37 은 **순서 효과의 추정치**이고 0 과 구별되지 않으므로(`p` = 0.46), 순서 효과의 크기도 부호도 이 데이터로는 정할 수 없다. 분리하려면 **같은 3 개 문서를 여러 순서로 돌리는 조건**이 필요한데 측정하지 않았다. 결론이 이 미지에 의존하지 않는 이유는 "순서가 상쇄된다" 는 가정이 아니라, **`d` = 0 과 `d` = 3 양쪽을 기준선으로 계산해 9 개 대비가 모두 유의하지 않음을 확인했기** 때문이다(2.3.1 절) |
| **⚠️ 한쪽만 올린 회계** | 5 · 6 절은 재순위의 배포 **비용**을 물리고 배포 **이득**(서빙 정확도)은 0 으로 둔다. 평가를 `d` = 0 으로 고정했으므로(2.4 절) 그 이득을 측정하지 않았다. `Q` 를 크게 잡으면 일회성 절약은 **어떤 방법이든** 본전이 될 수 없다(`B*` ∝ 1/Q → 0). 따라서 이 보고서가 말할 수 있는 것은 **"학습 라운드를 줄이는 경로만으로는 되살 수 없다"** 이고, "재순위가 경제성이 없다" 는 아니다. 후자를 말하려면 서빙 이득을 함께 재는 실험이 필요하다 |
| **⚠️ 치환검정의 바닥** | 시드 4 개에서 대응 치환검정이 낼 수 있는 최소 양측 `p` 가 **0.125** 다(2⁴ = 16 가지 부호 배열). 데이터가 아무리 깨끗해도 `p` < 0.05 가 **구조적으로 불가능**하다 — 관측된 최소 `p` 가 0.127 로 그 바닥에 붙어 있다. `within_noise` 판정은 이 설계가 낼 수 있는 유일한 결과이며, **시드 6 개부터 0.031 로 가능해진다**(7.5 절) |
| **장치 속도 가정** | 손익분기 대역폭은 이 가정에 **비례**한다. 비례상수일 뿐이라 **부호는 바꾸지 못한다** — 아낀 바이트가 음수인 네 깊이는 어떤 장치 속도에서도 0 이다. 다만 `d` = 25 의 `B*` 는 장치 속도에 비례하므로, 가정한 10¹² FLOP/s 보다 빠른 장치라면 그 구간이 선언한 범위 안으로 올라올 수 있다 — 질문 1,000 개에서는 약 **6 배**, 질문 10 만 개에서는 약 **600 배** 빠른 장치가 필요하다 (6 절) |

**측정 장치 자체는 작동했다.** 새 문서 비율이 0 에서 52.5 % 로 단조 증가했고, 통제는
0 을 유지했으며, 24 개 run 이 동일한 1.74 GB 를 썼고, 평가 문서는 전 조건에서 소수점
셋째 자리까지 같았다. 끊긴 곳은 **"좋은 문서 → 더 잘 배움"** 이다.
