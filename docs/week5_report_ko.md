# 5주차 — 재순위 계산으로 통신량을 되샀는가

**과제:** 검색 계산으로 통신량을 되사기 — 연합 LLM 미세조정에서 클라이언트 측
재순위의 환율
**범위:** Subtask 1.4

---

## 한 장 요약

**묻는 것.** 연합학습에서 가장 비싼 것은 통신이다. 클라이언트가 **더 좋은 문서로
학습하면 더 적은 라운드로 목표에 도달하고**, 라운드가 줄면 통신량이 준다 — 이것이
이 과제의 가설이다. 문서를 고르는 데는 계산이 든다. 그래서 묻는다:

> **계산을 더 써서 통신량을 얼마나 되샀는가?**

**한 것.** 4 주차가 만든 24 개의 학습 곡선을 읽어, 깊이별로 "같은 점수에 몇 라운드
만에 도달했나" 를 재고, 그 차이를 바이트로 환산해 재순위 계산량과 나눴다.

**나온 것.** **되사지 못했다.** 그리고 어느 고리에서 끊겼는지가 특정된다.

| 가설의 고리 | 결과 |
|---|---|
| 깊이를 올리면 → 더 좋은 문서가 프롬프트에 들어간다 | ✅ **작동** — 새 문서 0 % → 52.5 % |
| 더 좋은 문서 → 모델이 더 잘 배운다 | ❌ **끊김** — 차이가 전부 측정 오차 안 |
| 더 잘 배움 → 라운드가 준다 | ❌ 통제 조건이 가장 자주 "절약" 했다 |
| 라운드 감소 → 통신량 절약 | — 잴 대상이 없다 |

**가장 중요한 한 가지.** `d` = 3 은 **문서를 바꿀 수 없는 조건**이다(이미 고른 3 개를
순서만 바꾼다). 그런데 이 조건이 진짜로 문서를 바꾼 모든 조건보다 성적도 좋고
라운드도 자주 아꼈다. **아무것도 바꾸지 않은 쪽이 이긴다면, 그 승패는 처리의 효과가
아니라 측정의 흔들림이다.**

**실패한 실험이 아니다.** 결론은 *"재순위는 쓸모없다"* 가 아니라 *"이 모델 규모와
이 예산에서는 재순위가 통신량을 되사지 못한다"* 이며, **어디서 끊기는지를 보인 것**이
기여다.

## 1. 이 보고서가 읽는 것

4 주차가 디스크에 남긴 24 개의 학습 곡선 `results/logs/runs/*.jsonl` **뿐이다.**
재학습은 없다. 비용 가정을 바꾸거나 목표 점수를 다시 쓸어도 로그만 다시 읽는다 —
3 주차가 모든 것을 파일로 기록한 이유가 이 분리다.

| | |
|---|---|
| 입력 | 곡선 24 개 (깊이 6 × 시드 4) |
| 목표 점수 | **63 개**, 전부 사용 |
| 산출 | 환율 10 개, 손익분기 곡면, 기전 판정 |
| 판정 | **`within_noise`** — 어떤 절약도 측정으로 분해되지 않음 |

## 2. 실험이 무엇을 바꿨나

### 2.1 깊이가 하는 일

모든 조건에서 **프롬프트에 들어가는 문서는 3 개**다. 바뀌는 것은 **몇 개 중에서
고르느냐**뿐이다.

| `d` | 하는 일 | 새 문서 비율 |
|---|---|---|
| 0 | 검색이 고른 3 개 그대로 | 0 % |
| **3** | **그 3 개를 다시 보고 순서만 바꿈** | **0 %** |
| 7 | 상위 7 개를 검토해 3 개 선택 | 36.2 % |
| 10 | 10 개 중 3 개 | 42.0 % |
| 25 | 25 개 중 3 개 | 49.8 % |
| 50 | 50 개 중 3 개 | 52.5 % |

"새 문서 비율" 은 프롬프트의 3 개 중 **원래 검색이라면 고르지 않았을** 문서의
비율이다. 깊이를 올릴수록 **단조로 커진다** — 처리는 설계대로 걸렸다.

**그런데 포화한다.** 깊이 10 에서 50 으로 **다섯 배** 올려도 새 문서 비율은 42 % 에서
52.5 % 로 **4 분의 1 만** 는다. 교차인코더가 올릴 만한 문서는 후보 목록 **앞쪽에
몰려 있고**, 뒤쪽을 더 뒤지는 것은 대부분 헛일이다.

> 이 포화가 뒤에서 중요해진다. **계산 비용은 깊이에 비례해 선형으로 늘어나는데,
> 그 대가로 얻는 처리 용량은 포화한다**(7 절).

### 2.2 "자리가 바뀐 것" 과 "문서가 바뀐 것" 은 다르다

프롬프트 3 개 자리를 두 가지로 센다.

| 세는 것 | 뜻 |
|---|---|
| **자리 변경** | 그 자리에 **다른 문서**가 왔는가 (순서가 바뀐 것도 포함) |
| **새 문서** | 그 문서가 **원래 검색이라면 안 골랐을** 것인가 |

둘의 차이가 중요하다.

| `d` | 자리 변경 | 새 문서 | 차이 |
|---|---|---|---|
| 3 | 45.0 % | **0 %** | **45.0 %p** |
| 7 | 64.8 % | 36.2 % | **28.6 %p** |
| 10 | 67.6 % | 42.0 % | 25.6 %p |
| 25 | 71.2 % | 49.8 % | 21.4 %p |
| 50 | 72.4 % | 52.5 % | **19.9 %p** |

**그 차이가 "원래 있던 3 개를 섞은 것" 이다.** `d` = 7 에서는 자리의 64.8 % 가
바뀌었지만 그중 새 문서는 36.2 % 뿐이고, 나머지 **28.6 %p 는 그냥 순서가 바뀐
것**이다.

그리고 깊이가 깊어질수록 이 간격이 좁아진다(45.0 → 19.9 %p). 즉:

> **얕은 깊이의 처리는 상당 부분이 순서 바꾸기이고, 깊어져야 내용 교체가 주가 된다.**

(두 값 모두 전 라운드 평균이다. 새 문서 비율은 검색 캐시가 2 주차에 얼어 있어
라운드마다 **정확히 같다** — 변한다면 그것이 결함이다.)

`d` = 3 을 통제로 둔 이유가 바로 이것이다. 자리는 45.0 % 바뀌는데 새 문서는 0 % 인
조건 — **순수하게 "순서 바꾸기" 만 하는 조건**이 있어야, 처리의 효과에서 그 성분을
빼낼 수 있다.

### 2.3 `d` = 3 — 이 측정의 자

3 개 중에서 3 개를 고르면 **그 3 개**다. 네 번째가 올라올 수 없다. 순서만 바뀐다.

```
d = 0 :  [A] [B] [C]
d = 3 :  [C] [A] [B]      <- 같은 문서, 다른 순서
d = 50:  [A] [X] [Y]      <- 새 문서가 들어옴
```

**성적이 달라질 이유가 없는 조건**을 일부러 넣었다. 그런데 실제로는 차이가 났다.

```
d = 3 과 d = 0 의 F1 차이  =  +0.31
```

**프롬프트 내용이 완전히 같은 두 조건이 0.31 점 차이가 난다.** 이것이 **아무것도
바꾸지 않아도 생기는 흔들림의 크기**다. 같은 시험을 두 번 봐도 점수가 조금 다른 것과
같다.

> **이 0.31 이 이 보고서 전체를 읽는 기준이다.** 어떤 처리 효과든 0.31 근처라면,
> 그것은 아무것도 바꾸지 않았을 때 생기는 크기와 같다.

### 2.4 평가는 전 조건에서 `d` = 0 으로 고정했다

`d` = 50 으로 학습한 모델도 **채점할 때는 `d` = 0 의 문서**를 받는다. 실제로 그렇게
되었음은 로그가 확인한다 — 평가 문서의 품질이 깊이에 무관하게 소수점 셋째 자리까지
같았다.

**왜 그래야 하는가.** 재순위가 점수를 올릴 수 있는 길이 둘인데, 둘이 전혀 다르다.

| 길 | 어떻게 | 통신량과 관계 |
|---|---|---|
| **학습** | 좋은 문서로 공부 → 모델이 좋아짐 | **있음.** 모델이 좋으면 라운드가 줄고, 라운드가 곧 바이트 |
| **서빙** | 시험 때 좋은 문서를 받음 → 같은 모델로 더 나은 답 | **없음.** 질문마다 재순위를 영원히 돌려야 하고 라운드와 무관 |

각 조건을 자기 깊이에서 채점했다면 두 길이 **더해져서 구분되지 않는다.** `d` = 50 이
높은 점수를 받아도 **모델이 좋아져서인지 시험 때 좋은 문서를 받아서인지** 알 수 없다.

그리고 서빙 쪽은 거의 확실히 점수를 올린다 — 2 주차에서 `d` = 50 의 문서 품질이
`d` = 0 보다 3.92 %p 높았다. **그 이득을 섞어 넣었다면 이 보고서는 "재순위가 통신량을
줄인다" 는 결론을 만들어냈을 것이다.** 실제로 줄인 것은 없는데도.

**대가와 그 처리.** 그래서 보고되는 점수는 실제 배치 시스템보다 낮다. 의도된 것이다.
서빙 이득을 버리는 것도 아니다 — 5 절의 비용 모델이 그것을 **질문당 계산 비용으로**
값을 매긴다.

## 3. 라운드를 몇 번 덜 썼나

### 3.1 재는 방법

통신량은 라운드에 비례한다(**라운드 1 회 = 29.5 MB**). 그래서 "얼마나 아꼈나" 는
"몇 라운드 덜 썼나" 와 같은 질문이다.

목표 점수를 정하고, 각 조건이 **몇 번째 라운드에 그 점수에 도달했는지** 세어 기준선과
비교한다.

```
기준선(d=0) 도달 라운드  −  해당 깊이 도달 라운드
      양수 → 덜 썼다 (이득)        음수 → 더 썼다 (손해)
```

도달 라운드는 평가 지점 사이를 직선으로 이어 읽는다. LoRA 는 몇 라운드 만에
수렴하므로 "9 라운드" 같은 정수로는 9 와 10 사이가 통째로 사라지고, 조건 간 차이는 그
안에 들어가기 때문이다.

### 3.2 목표 점수를 정하는 법 — 고르지 않는다

목표를 하나 고르면 그 선택이 결론을 정한다. 실제로 그 위험이 현실이 된 적이 있다:
목표 25.02 점 한 곳에서는 `d` = 25 만 이득이었고, 그 한 값이 판정을 뒤집었다. 전체로
보면 같은 깊이가 손해다.

그래서 목표를 **고르지 않고, 기준선이 실제로 받은 점수를 전부 쓴다.**

```
기준선(d = 0) run 4 개 × 평가 20 회  =  점수 80 개
```

그중 둘을 뺀다.

| 빼는 것 | 몇 개 | 왜 |
|---|---|---|
| **18.13 점 미만** | 3 개 | 기준선이 **라운드 1 에 이미** 넘은 점수. 전 조건이 1 라운드에 도달해 비교가 안 됨 |
| **28.14 점 초과** | 14 개 | 끝까지 가도 **도달하지 못하는 시드**가 생김 |

**80 − 17 = 63 개.** 두 경계도 데이터가 정한다 — 아래는 네 시드의 라운드 1 점수 중
최대, 위는 네 시드 최고점 중 최소다. **임의로 정한 숫자가 하나도 없다.**

### 3.3 결과

63 개 목표 각각에서 승패를 매기고 세었다.

| `d` | 기준선을 이긴 목표 | 그중 오차보다 큰 것 | 보통 (중앙값) |
|---|---|---|---|
| **3** *(통제)* | **41 / 63** | **26 / 63** | **0.15 라운드 빠름** |
| 7 | 19 / 63 | 10 / 63 | 0.56 라운드 느림 |
| 10 | 20 / 63 | 16 / 63 | 0.21 라운드 느림 |
| 25 | 24 / 63 | 9 / 63 | 0.11 라운드 느림 |
| 50 | 15 / 63 | 7 / 63 | 0.37 라운드 느림 |

**"오차보다 큰 것"** — 시드 4 개로 재므로 측정 자체가 ±0.2 ~ ±0.9 라운드 흔들린다.
이긴 폭이 그보다 작으면 이겼다고 말할 수 없다.

**"보통"** — 63 개를 줄 세운 **한가운데 값**이다. 평균이 아닌 이유는, 목표를 높게
잡으면 곡선이 평평해져(25.02 점에 9 라운드, 28.14 점에 38.7 라운드) 작은 점수 차이가
라운드 10 개로 번역되고 값이 ±11 까지 튀기 때문이다. 그 구간을 **잘라내지는 않았다** —
어디서 자를지가 또 임의 선택이 되므로, 대신 극단값에 흔들리지 않는 통계를 썼다.

### 3.4 이 표가 말하는 것

**통제가 1 위다.** `d` = 3 은 문서를 바꿀 수 없는데 63 개 중 41 개를 이겼고, 확실한
승리도 26 개로 가장 많다. 진짜로 문서를 바꾼 네 조건은 15 ~ 24 개에 그치고 **보통은
전부 느리다.**

> 아무것도 바꾸지 않은 조건이 가장 자주 이긴다면, 그 승패는 처리의 효과가 아니라
> **측정의 흔들림**이다.

### 3.5 보간을 쓰지 않는 두 번째 확인

도달 라운드는 곡선 사이를 이어 읽은 값이라, 그 계산 자체가 의심받을 수 있다. 그래서
**같은 통신량을 쓴 지점에서 점수를 직접 비교**하는 방법으로도 확인했다.

| `d` | 차이가 0 과 구별된 지점 |
|---|---|
| **3** *(통제)* | **8 / 20** |
| 7 | 4 / 20 |
| 10 | **8 / 20** |
| 25 | 5 / 20 |
| 50 | 6 / 20 |

통제가 `d` = 10 과 **같은 횟수**다. 보간을 전혀 쓰지 않는 방법에서도 같은 결론이 나온다.

## 4. 계산을 얼마나 썼나

비용은 두 항이다.

```
일회성   인덱싱    = 코퍼스 전체를 한 번 임베딩
반복     재순위    = 질문 수 × 깊이 × 쌍당 계산량
```

| `d` | 질문 1 개당 계산 | 이 CPU 에서 |
|---|---|---|
| 3 | 1.63 × 10¹⁰ FLOPs | 0.15 초 |
| 7 | 3.81 × 10¹⁰ | 0.34 초 |
| 10 | 5.44 × 10¹⁰ | 0.49 초 |
| 25 | 1.36 × 10¹¹ | 1.23 초 |
| 50 | 2.72 × 10¹¹ | **2.46 초** |

깊이에 **정비례**한다. 쌍당 계산량은 4 주차에서 실측했다(해석적 추정과 2 배 이내로
일치).

**일회성 항은 조건을 가르지 못한다.** 깊이와 무관하게 같은 값이기 때문이다. 이것이
**재순위 깊이를 처리 축으로 삼은 이유**다 — 깊이는 질문당 **반복** 비용이라, 라운드당
통신량과 같은 단위에서 맞바꿀 수 있다.

두 가정을 **모두** 보고한다. 어느 쪽이 맞는지는 배치 상황이 정하므로 고르지 않는다.

| 가정 | 뜻 |
|---|---|
| `amortised` | RAG 가 이미 배치되어 인덱스가 존재 → 일회성 항 0 |
| `with_indexing` | 이 학습을 위해 인덱스를 새로 구축 → 일회성 항 부과 |

## 5. 환율 — 가정이 들어가지 않는 숫자 하나

```
환율 = 아낀 바이트 ÷ 더 쓴 계산량
```

대역폭도 장치도 들어가지 않는다. 특정 배치의 결론은 이 숫자에 그 배치의 값을 곱한
것이다.

| `d` | 아낀 바이트 | 환율 (인덱스 있음) | 환율 (인덱스 구축) |
|---|---|---|---|
| 3 | **−17.8 MB** | −1.09 × 10⁻⁸ | −6.57 × 10⁻⁹ |
| 7 | **−60.6 MB** | −1.59 × 10⁻⁸ | −1.24 × 10⁻⁸ |
| 10 | **−30.4 MB** | −5.59 × 10⁻⁹ | −4.66 × 10⁻⁹ |
| 25 | +2.9 MB | +2.14 × 10⁻¹⁰ | +1.98 × 10⁻¹⁰ |
| 50 | **−4.3 MB** | −1.59 × 10⁻¹⁰ | −1.53 × 10⁻¹⁰ |

**음수는 "계산을 쓰고 바이트도 더 썼다" 는 뜻이다.** 열 개 중 여덟 개가 음수다.

**두 가정의 부호가 모든 깊이에서 같다.** 즉 이 결론은 "인덱스를 이미 갖고 있는가" 라는
배치 질문에 의존하지 않는다. 인덱싱을 물리면 절댓값만 줄고 방향은 그대로다.

유일한 양수인 `d` = 25 는 3.3 절에서 보았듯 63 개 중 24 개에서만 이기고 보통은 지는
조건에서 나온 값이다.

## 6. 손익분기 — 어떤 링크에서 이득인가

환율에 배치 조건을 곱하면 **초**라는 공통 단위가 된다.

```
아낀 전송 시간 = 아낀 바이트 ÷ 대역폭
더 쓴 계산 시간 = 총 계산량 ÷ 장치 속도
```

재순위는 **느린 링크**에서 유리하다 — 느릴수록 바이트가 비싸고, 그 바이트가 바로
재순위가 되사려는 것이기 때문이다.

| 질문 수 | 손익분기 대역폭 |
|---|---|
| 1,000 | **0 Mbps** |
| 10,000 | 0 Mbps |
| 100,000 | 0 Mbps |
| 1,000,000 | 0 Mbps |
| 10,000,000 | 0 Mbps |

**0 은 "그런 링크가 없다" 는 뜻이다.** 보통 이 표는 *"X Mbps 보다 느린 링크에서는
이득"* 을 알려준다. 아낀 바이트가 음수이면 아무리 느린 링크에서도 이득이 되지 않으므로
그런 `X` 가 존재하지 않는다.

## 7. 가설의 사슬은 어디서 끊겼나

### 7.1 제안했던 경로

```
깊이 ↑ → 문서 품질 ↑ → 클라이언트가 같은 과제를 배움
       → 업데이트 발산 ↓ → 필요 라운드 ↓
```

가운데 "클라이언트가 서로 얼마나 다른 방향으로 학습하는가" 를 **발산**이라 한다.
8 개가 제각각이면 서버가 평균 내기 어렵고, 그래서 라운드가 더 필요하다는 것이
가설이었다.

### 7.2 발산은 거의 움직이지 않았다

| `d` | 처리 강도 | 발산 |
|---|---|---|
| 0 | 0.00 | 1.3234 |
| 3 | 0.45 | 1.3218 |
| 7 | 0.65 | 1.3143 |
| 10 | 0.68 | 1.3151 |
| 25 | 0.71 | 1.3162 |
| 50 | 0.72 | **1.3132** |

처리 강도는 0 에서 0.72 로 **크게** 바뀌었는데, 발산은 1.3234 에서 1.3132 까지
**0.77 % 만** 움직였다. 그리고 깊이 순서대로 줄어들지도 않는다 — `d` = 7 이 `d` = 10
이나 `d` = 25 보다 낮다.

(발산은 학습 **초반 10 라운드**의 평균이다. 처리가 학습 방향에 영향을 준다면 가장
먼저 드러날 구간이기 때문이다.)

### 7.3 상관계수를 그대로 읽으면 안 된다

```
처리 강도 ↔ 발산 감소     +0.91
발산 감소 ↔ 라운드 절약   −0.88
```

**첫 줄만 보면 가설이 지지되는 것처럼 보인다.** 이 보고서에서 가장 오해하기 쉬운
숫자이므로 둘을 함께 읽어야 한다.

**(i) 거의 움직이지 않는 양들 사이의 상관이다.** 0.77 % 변동이다. 상관계수는 방향만
말하고 크기를 말하지 않는다.

**(ii) 다음 고리의 부호가 반대다.** 가설은 *"발산이 줄면 라운드가 준다"* 이므로
**양수**여야 하는데 **−0.88** 이다. 발산이 가장 많이 줄어든 깊이들이 라운드를 가장
많이 **더** 썼다.

> 앞 고리는 **변화량이 측정 불가 수준**이고, 뒤 고리는 **부호가 반대**다. 제안된
> 경로는 지지되지 않는다.

### 7.4 판정

```
within_noise — 가장 큰 절약은 d = 3 (통제)의 0.15 라운드이고, 63 개 목표 중
               26 개에서만 오차를 넘는다. 어떤 깊이도 과반의 목표에서 절약을
               분해하지 못한다.
```

판정 규칙은 한 줄이다 — **절약이 자기 오차를 넘는 목표가 과반(63 중 32 이상)이어야
"절약이 관측되었다" 고 한다.** 어느 한 점도 판정을 뒤집을 수 없다.

## 8. 깊이별 절충

네 축을 한자리에 놓으면 모양이 보인다.

| `d` | 질문당 계산 | 새 문서 비율 | F1 (통제 대비) | 라운드 절약 |
|---|---|---|---|---|
| **0** | 0 초 | 0 % | −0.31 | — |
| **3** *(통제)* | 0.15 초 | 0 % | — | +0.15 |
| **7** | 0.34 초 | 36 % | −0.24 | −0.56 |
| **10** | 0.49 초 | 42 % | +0.29 | −0.21 |
| **25** | 1.23 초 | 50 % | −0.20 | −0.11 |
| **50** | 2.46 초 | 53 % | −0.03 | −0.37 |

**(a) 깊이를 올리면 일관되게 좋아지는가 — 아니다.** 통제 대비 F1 은 −0.24, +0.29,
−0.20, −0.03 으로 **부호조차 일정하지 않고**, 라운드 절약은 네 처리 모두 음수다.

**(b) 수확 체감은 어디서 나타나는가 — 성능이 아니라 문서 품질에서.** 성능에는 체감할
이득 자체가 없다. 체감은 2.1 절에서 보았다 — 깊이를 다섯 배 올려도 새 문서 비율은
4 분의 1 만 는다. 그런데 **계산은 깊이에 정비례해 늘어난다**(0.34 → 2.46 초, **7 배**).
비용은 선형, 효과는 포화. 꺾이는 지점은 `d` = 10 과 `d` = 25 사이다.

**(c) 최선의 절충 깊이는 — `d` = 0.** 어떤 깊이도 지불한 계산만큼을 돌려주지 못한다.
`d` = 50 은 질문마다 2.46 초를 영구적으로 쓰면서 통신량을 4.3 MB **더** 쓴다.

## 9. 이 결론이 서는 조건

결론은 *"재순위가 쓸모없다"* 가 아니라 *"이 조건에서 재순위가 통신량을 되사지
못한다"* 이다. 조건을 밝힌다.

| 한계 | 내용 |
|---|---|
| **모델이 작다** | SmolLM2-135M 하나. 더 좋은 문서를 활용할 능력이 부족한 크기일 수 있다 |
| **시드가 4 개** | 측정이 ±0.16 ~ ±0.47 점 흔들린다. 0.3 점 효과를 가르려면 시드 16 개 = 64 run = 90 시간이 필요하다 |
| **곡선이 수렴하지 않았다** | 59 라운드로 고정했는데 대부분의 곡선이 라운드 50 이후에 최고점을 가진다 |
| **깊이 6 단** | 5 · 20 · 30 은 측정하지 않았다. 관측된 효과가 전부 통제가 정한 흔들림(0.31 점) 안에 있어, 사다리를 촘촘히 해도 가르지 못하는 것이 같기 때문이다 |
| **장치 속도 가정** | 손익분기 대역폭은 이 가정에 비례하지만, 아낀 바이트가 음수이므로 어떤 값에서도 부호는 바뀌지 않는다 |

**측정 장치 자체는 작동했다.** 새 문서 비율이 0 에서 52.5 % 로 단조 증가했고, 통제는
0 을 유지했으며, 24 개 run 이 동일한 1.74 GB 를 썼고, 평가 문서는 전 조건에서 소수점
셋째 자리까지 같았다. 끊긴 곳은 **"좋은 문서 → 더 잘 배움"** 이다.
